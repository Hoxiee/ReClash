# Профили

Справочник формата профиля RCX: ключи, значения по умолчанию, наследование, привязки и лимиты.

## Документ

Профиль — одно отображение YAML; неизвестные ключи — ошибка. В приложении профиль называется поведением.

```yaml title="bypass-de.rcx.yaml"
rcx: 1
title: Germany first
description: Prefers servers that exit in Germany and open the test page.
level: advanced
pool: { exclude: 'type = http' }
tags:
  premium: 'name ~ /premium|vip/i'
checks:
  page: { http: 'https://example.com/', expect: [200] }
prefer:
  - { label: German exit, when: 'exit.country = DE and passes(page)' }
  - { label: Premium, when: 'tag(premium) and not dead' }
  - { label: Any working, when: 'not dead', last-resort: true }
rank: { by: latency, tolerance: 40 }
switch: { improve: true, feel: calm, max-per-hour: 1 }
stranded: direct
energy: balanced
```

## Ключи

| Ключ | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `rcx` | целое | 1 | Версия формата; больше 1 отвергается. |
| `title` | строка | id | Отображаемое имя. |
| `description` | строка | — | Однострочное описание в списках выбора. |
| `level` | `simple` \| `advanced` | `simple` | Насколько подробно его показывает редактор. |
| `extends` | id профиля | — | Базовый профиль; см. [Наследование](#inheritance). |
| `pool` | `{include, exclude}` | все элементы | Серверные условия, сужающие набор элементов. |
| `tags` | имя → серверное условие | — | Именованные наборы серверов для `tag(name)`. |
| `checks` | id → проверка | — | Запросы для `passes(id)` и `fails(id)`. |
| `prefer` | список уровней | один уровень `Working` (`not dead`) | Упорядоченные уровни серверов. |
| `rank.by` | `latency` \| `stability` | `latency` | Формула оценки; см. [Оценка](engine.md#score). |
| `rank.tolerance` | целое, мс | 0 | Бонус текущему серверу. |
| `switch.feel` | `calm` \| `balanced` \| `eager` | `balanced` | Набор значений для полей `switch`. |
| `switch.improve` | логическое | `false` | Переходить на более быстрый сервер в пределах уровня. |
| `switch.dwell` | длительность | из набора | Минимальное время между переключениями ради улучшения. |
| `switch.min-gain-ms` | целое | из набора | Минимальный выигрыш в миллисекундах. |
| `switch.min-gain-pct` | целое | из набора | Минимальный выигрыш в процентах от оценки текущего. |
| `switch.confirm` | целое | из набора | Сколько свежих замеров подряд должен выиграть кандидат. |
| `switch.max-per-hour` | целое | из набора | Переключений ради улучшения в час. |
| `stranded` | `hold` \| `direct` \| `group:<name>` | `hold` | Действие, когда ни один элемент не пригоден. |
| `energy` | `eco` \| `balanced` \| `precise` | `balanced` | Бюджет проб; см. [Бюджеты](engine.md#budgets). |
| `network.diagnose` | имя → диагностика | — | Прямые пробы для сетевых условий. |
| `network.kinds` | список правил типов | — | Типы сетей; побеждает первое совпадение. |
| `on` | тип → слой | — | Изменения в одном типе сети. |
| `direct-split` | сетевое условие | — | Когда может включаться прямой обход. |
| `egress-verify.echo` | список URL | два встроенных сервиса | Эхо-сервисы страны выхода. |
| `egress-verify.agree` | 0–3 | 2 (0 означает 2) | Сколько разных согласных источников нужно. |
| `l10n` | язык → исходная строка → текст | — | Переводы собственных строк профиля. |

Длительности пишутся в синтаксисе Go (`90s`, `1h30m`) и не могут быть отрицательными. См.
[Наборы характера](engine.md#feel-presets).

## Пул

`include` и `exclude` — [серверные условия](conditions.md). Элемент остаётся, если `include` не ложно и `exclude` не
истинно; неизвестный факт сам по себе ни допускает, ни убирает элемент. Не-серверы (`DIRECT`, `REJECT` и подобные)
никогда не пригодны.

## Уровни

```yaml
# fragment
prefer:
  - { label: Fast home, when: 'country = NL and latency < 80ms' }
  - { label: Any, when: 'not dead' }
  - { label: Fallback, when: 'not dead', last-resort: true }
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `label` | строка | Показывается в приложении; пустая метка отображается как `Tier N`, где N — позиция. |
| `when` | серверное условие | Элементы, для которых оно истинно, входят в уровень. |
| `last-resort` | логическое | Уровень уступает всем остальным, где бы он ни стоял. |

Элемент входит в первый уровень, чьё условие истинно. Выбор переходит к следующему уровню, только когда все серверы
текущего уровня исключены или мертвы.

## Проверки

```yaml
# fragment
checks:
  web: { http: 'https://example.com/generate_204', expect: [204] }
  port: { tcp: 'example.net:443', optional: true }
  hello: { tls: '203.0.113.7:443', sni: example.org }
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `http` | URL | Запрос `HEAD` через сервер; переадресации не выполняются. |
| `tcp` | `host:port` | TCP-соединение через сервер. |
| `tls` | `host:port` | TLS-рукопожатие через сервер; сертификат не проверяется. |
| `sni` | строка | Имя сервера для `tls`; по умолчанию — узел, если это имя. |
| `expect` | список 100–599 | Только для `http`; без него проходит любой ответ. |
| `optional` | логическое | Сбой мягкий: `passes(id)` и `fails(id)` остаются ложными. |

Нужно ровно одно из `http`, `tcp` или `tls`. Проверка выполняется, только когда её использует условие, как дополнение к
успешной пробе. Узел вне домена провайдера и встроенных адресов требует согласия, если профиль пришёл от провайдера;
см. [Согласие](sharing.md#consent).

## Сеть

```yaml
# fragment
network:
  diagnose:
    home: { tcp: ['77.88.8.8:443', '77.88.8.1:443'] }
    foreign: { tls: ['1.1.1.1:443'] }
  kinds:
    - { kind: portal, when: network.portal, pause: true }
    - { kind: whitelist, when: 'home ok and foreign fail' }
```

Диагностика — именованный список целей: URL для `http` или пары `host:port` для `tcp` и `tls`. Цели опрашиваются напрямую
через исходящее соединение `DIRECT`. `<name> ok` истинно, когда ответила любая цель; `<name> fail` — когда опрошены все
цели и ни одна не ответила.

| Поле типа | Тип | Описание |
| --- | --- | --- |
| `kind` | имя | `[a-z0-9-]`, 1–24 символа. |
| `when` | сетевое условие | Распознаёт тип. |
| `pause` | логическое | Держать текущий сервер и остановить проверки в этом типе. |

Правила распознавания — в разделе [Типы сетей](engine.md#network-kinds).

## Изменения по типам сетей

```yaml
# fragment
on:
  whitelist:
    prefer:
      - { label: Bypass node, when: 'tag(bypass) and not dead' }
    switch: { feel: eager }
```

`on.<kind>` может задавать `pool`, `prefer`, `rank`, `switch`, `stranded` и `energy`. Тип должен быть объявлен в
`network.kinds`, иначе компиляция падает с `the profile declares no network kind <kind>`. Слой накладывается на профиль
как потомок при [наследовании](#inheritance); затем применяется привязка пользователя.

## Прямой обход

`direct-split` — сетевое условие. Пока оно истинно и пользователь включил **Прямые сайты через эту группу**, соединения,
совпавшие с явным правилом `DIRECT`, идут через группу. Исключения и состояния:
[Прямой обход](engine.md#direct-split).

## Переводы

```yaml
# fragment
l10n:
  ru: { Germany first: Сначала Германия, German exit: Выход в Германии }
```

Ключи — собственные исходные строки профиля: название, описание и метки уровней. Приложение показывает язык пользователя,
иначе исходный текст. Тег языка — 2–3 строчные буквы, необязательно с регионом из 2–8 букв или цифр (`ru`, `zh-CN`).

## Наследование

`extends` называет базовый профиль; цепочка не глубже 4 уровней и не может замыкаться.

| Ключ | Правило слияния |
| --- | --- |
| Скаляры (`title`, `level`, `rank.by`, `stranded`, `energy`, …) | Побеждает потомок, если задан; `rank.tolerance: 0` не переопределяет. |
| `pool` | Сужается: `include` соединяются через `and`, `exclude` — через `or`. |
| `tags`, `checks`, `network.diagnose`, `l10n` | Сливаются по ключам; `l10n` — по языкам и строкам. |
| `prefer` | Заменяется, если у потомка есть хотя бы один уровень. |
| `switch` | `feel` потомка сбрасывает остальные поля к его набору (`improve` сохраняется); затем явные поля переопределяют. |
| `on` | Сливается по типам; `on.<kind>` потомка заменяет родительский. |
| `network.kinds`, `egress-verify.echo` | Заменяются целиком. |
| `egress-verify.agree` | Побеждает потомок, если задан. |

Ошибки: `extends itself`, `extends more than 4 levels deep`, `profile <id> not found`.

## Привязки

Привязка прикрепляет профиль к одной группе-селектору. Подписка записывает её как `rcx:` у группы; приложение хранит
привязку пользователя отдельно для каждой подписки.

```yaml
# fragment
proxy-groups:
  - name: Proxy
    type: select
    proxies: [NL 1, NL 2, DE 1]
    rcx:
      profiles: [fast, builtin/stable]
      default: fast
      pool: { exclude: 'name ~ /test/' }
      chips:
        - { label: Netherlands, include: 'country = NL' }
```

| Ключ | Тип | Описание |
| --- | --- | --- |
| `profiles` | список id | Профили, предлагаемые для группы. |
| `default` | id | Используется, когда `profile` пуст или не найден. |
| `profile` | id | Выбранный профиль. |
| `pool` | `{include, exclude}` | Сужает пул профиля. |
| `prefer` | список уровней | Заменяет порядок профиля для этой группы. |
| `feel` | характер | Сбрасывает поля переключения к этому набору. |
| `energy` | энергия | Переопределяет энергию профиля. |
| `chips` | список `{label, include}`, не больше 12 | Пулы в одно касание под **Выбирать из**; неверные отбрасываются. |

Привязка пользователя заменяет `profile`, `pool`, `feel` и `energy`, заменяет `prefer`, если он не пуст, и добавляет свои
чипы к чипам провайдера. Подписка не может включить прямой обход. Id профиля разрешается по порядку: `profile`, `default`,
`builtin/simple`; отсутствующий `profile` сообщается как `profile.missing`. Поверх применяются программы сценария; см.
[Программы](scenarios.md#programs). Если собственный `on.<kind>` профиля задаёт `prefer` для текущего типа
сети, этот порядок важнее обоих.

## Лимиты

| Что | Лимит |
| --- | --- |
| Документ | 64 КиБ |
| Уровни | 16 |
| Теги | 32 |
| Проверки | 8 |
| Диагностики | 8, у каждой 1–4 цели |
| Типы сетей, записи `on` | по 8 |
| Эхо-сервисы | 4, URL `http(s)` |
| Глубина `extends` | 4 |
| Чипы | 12 |
| `l10n` | 16 языков, по 64 строки, 1–160 символов в строке |
| Условие | 2048 символов; см. [Лимиты](conditions.md#limits) |
