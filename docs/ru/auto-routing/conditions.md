# Условия

Справочник языка условий RCX: грамматика, поля, функции, трёхзначная логика и лимиты.

## Где встречаются условия

| Контекст | Вид | Можно использовать |
| --- | --- | --- |
| `pool.include`, `pool.exclude`, `prefer[].when`, чипы, программы сценария | Серверное | Серверные и сетевые поля, `tag()`, `passes()`, `fails()` |
| Значения `tags` | Серверное | Серверные и сетевые поля, `passes()`, `fails()`; без `tag()` |
| `network.kinds[].when`, `direct-split` | Сетевое | Только сетевые поля и `<diagnostic> ok` или `fail`; серверное поле даёт ошибку `is about a server, not the network` |

Пустое условие всегда истинно.

## Грамматика

```text
condition  = or
or         = and { "or" and }
and        = unary { "and" unary }
unary      = "not" unary | "(" or ")" | predicate
predicate  = boolfield
           | strfield ( "=" | "!=" ) value
           | strfield "in" "[" value { "," value } "]"
           | strfield "~" ( regex | string )
           | "latency" ( "=" | "!=" | "<" | "<=" | ">" | ">=" ) number
           | ( "tag" | "passes" | "fails" ) "(" name ")"
           | diagnostic ( "ok" | "fail" )
value      = word | string
word       = { letter | digit | "_" | "-" | "." | ":" }
string     = "'" { any but "'" } "'" | '"' { any but '"' } '"'
regex      = "/" { any, "\/" for a slash } "/" [ "i" ]
number     = digits [ "ms" ]
```

- Ключевые слова (`and`, `or`, `not`, `in`, `ok`, `fail`) и имена полей не зависят от регистра. Сильнее всех связывает
  `not`, затем `and`, затем `or`.
- Одиночный `!` — ошибка: `use 'not' instead of '!'`.
- В строках нет экранирования; значение с пробелами, эмодзи или символами вне `word` берите в кавычки.
- Регулярное выражение — RE2, без привязки; единственный флаг — `i`. Строка в кавычках после `~` тоже читается как шаблон.
- Сравнения строк через `=`, `!=` и `in` не учитывают регистр.

## Поля

### Серверные поля

| Поле | Тип | Значение | Неизвестно, когда |
| --- | --- | --- | --- |
| `name` | строка | Имя элемента | никогда |
| `provider` | строка | Провайдер прокси, который обслуживает элемент | никогда |
| `type` | строка | Тип адаптера mihomo, например `Vless` или `Shadowsocks` | никогда |
| `server` | строка | Узел или адрес сервера | никогда |
| `country` | страна | Проверенная страна выхода, иначе страна из имени (флаг или английское название) | никогда; пустое считается известным |
| `exit.country` | страна | Проверенная страна выхода | ещё не проверена |
| `entry.country` | страна | Страна `server` по GeoIP, если это IP-адрес | `server` — имя или его нет в базе |
| `udp` | логическое | Элемент поддерживает UDP | никогда |
| `alive` | логическое | Здоровье `alive` | никогда |
| `dead` | логическое | Здоровье `dead` | никогда |
| `measured` | логическое | Есть замеры задержки за последние 6 часов | никогда |
| `current` | логическое | Это выбранный элемент | никогда |
| `latency` | число, мс | Медианная задержка | никогда; сравнения ложны, пока нет `measured` |

Страны — коды ISO 3166-1 alpha-2 (`NL`, `DE`).

### Сетевые поля

| Поле | Тип | Значение |
| --- | --- | --- |
| `network.kind` | строка | Подтверждённый тип сети |
| `network.transport` | строка | `wifi`, `ethernet`, `cellular` или `other` на Android |
| `network.portal` | логическое | Система сообщает о портале авторизации |
| `metered` | логическое | Сеть лимитная |

Сетевые поля неизвестны, пока платформа не сообщила о сети; `network.kind` неизвестен, пока тип не подтверждён.

## Функции

| Форма | Истинна, когда | Ошибки |
| --- | --- | --- |
| `tag(name)` | Условие тега точно истинно для элемента; неизвестное считается ложным. | `unknown tag`; `tag(…) is not allowed here` |
| `passes(id)` | Последний результат проверки `id` — прохождение. | `unknown check` |
| `fails(id)` | Последний результат проверки `id` — жёсткий сбой. | `unknown check` |
| `<diagnostic> ok` | Ответила любая цель диагностики. | `<name> needs ok or fail` |
| `<diagnostic> fail` | Опрошены все цели, и ни одна не ответила. | |

Проверка, которая ни разу не выполнялась, неизвестна. Сбой проверки с `optional` делает ложными и `passes()`, и
`fails()`. Прохождение меняется только после двух сбоев подряд; см. [Свидетельства](engine.md#evidence).

## Трёхзначная логика

Каждый предикат истинен, ложен или неизвестен; они объединяются по логике Клини.

| A | B | A and B | A or B | not A |
| --- | --- | --- | --- | --- |
| true | unknown | unknown | true | false |
| false | unknown | false | unknown | true |
| unknown | unknown | unknown | unknown | unknown |

Следствия:

- Уровень принимает элемент, только когда его условие истинно. Неизвестное делает элемент `pending`, который планировщик может проверить.
- `pool.include` допускает неизвестное; `pool.exclude` убирает только истинное.
- Неизвестное правило типа сети останавливает распознавание, пока не прояснится.

## Лимиты

| Что | Лимит |
| --- | --- |
| Длина условия | 2048 символов |
| Вложенность | 16 уровней; каждый `not` и каждая скобка добавляют один |
| Длина регулярного выражения | 512 символов |

## Примеры

| Условие | Смысл |
| --- | --- |
| `not dead` | Любой элемент, не помеченный мёртвым |
| `country in [NL, DE] and latency < 120ms` | Нидерланды или Германия, замер меньше 120 мс |
| `exit.country != RU and passes(open)` | Проверенный выход не из RU, открывающий проверку |
| `name ~ /premium/i` | Имя содержит `premium` в любом регистре |
| `name ~ '⚡ RU'` | Имя содержит буквальный текст `⚡ RU` |
| `udp and not type = Http` | Поддерживает UDP и не HTTP-прокси |
| `metered or network.transport = cellular` | Сетевое условие: лимитная сеть или мобильные данные |
| `home ok and foreign fail` | Сетевое условие: отвечает только диагностика `home` |
