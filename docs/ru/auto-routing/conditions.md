# Условия

**Условие** — небольшое выражение, отвечающее на вопрос о сервере: «подходит ли он?». Условия используются в `pool.include`, `pool.exclude`, `tags` и в поле `when` каждого шага `prefer`. В параметрах сети (`network.kinds`, `direct-split`) они описывают саму сеть.

Примеры с пометкой `# fragment` являются фрагментами. Все остальные — полные профили, проходящие проверку [`rcxlint`](sharing.md#инструмент-rcxlint). Условие показано внутри профиля, чтобы его можно было скопировать без изменений.

## Краткий обзор

```yaml
rcx: 1
title: Quick tour
pool:
  exclude: name ~ /(?i)test/
prefer:
  - label: Norway, fast
    when: country = NO and latency < 120
  - label: Nordics
    when: country in [NO, SE, FI, DK]
  - label: Anything
    when: not dead
```

- `country = NO` сравнивает поле со значением.
- `latency < 120` сравнивает числовое значение (миллисекунды).
- `country in [NO, SE, FI, DK]` проверяет вхождение в набор.
- `name ~ /(?i)test/` ищет совпадение с регулярным выражением без учёта регистра.
- `not dead` применяет `not` к полю «да/нет».
- Условия можно объединять с помощью `and`, `or`, `not` и скобок.

## Грамматика

```text
condition   = or
or          = and { "or" and }
and         = not { "and" not }
not         = "not" not | primary
primary     = "(" condition ")" | test
test        = bool-field
            | string-field ( "=" | "!=" ) value
            | string-field "in" "[" value { "," value } "]"
            | string-field "~" regex
            | number-field ( "=" | "!=" | "<" | "<=" | ">" | ">=" ) number [ "ms" ]
            | "tag" "(" word ")"
            | "passes" "(" word ")" | "fails" "(" word ")"
value       = word | 'quoted' | "quoted"
regex       = /pattern/flags | 'quoted' | "quoted"
```

Основные правила:

- **Приоритет операторов**: сначала `not`, затем `and`, затем `or`. Если сомневаетесь, используйте скобки.
- `!` не поддерживается. Пишите `not` (сообщение об ошибке подсказывает «use 'not'»).
- *Слово* может содержать буквы, цифры, `_ - . :`. Всё остальное (пробелы, `*`, флаги) заключайте в кавычки.
- При сравнении строк регистр не учитывается (`country = no` эквивалентно `country = NO`).
- В YAML заключайте всё условие в кавычки, если оно содержит `: `, начинается с `[`, `{`, `*`, `&`, `!` или `#`. Обычно условие, начинающееся с имени поля, безопасно, но при сомнениях используйте одинарные кавычки: `when: 'name ~ /a|b/'`.

## Поля

Поля оцениваются для одного сервера в сети, к которой он сейчас подключён.

### Поля сервера

| Поле | Тип | Операторы | Значение |
| --- | --- | --- | --- |
| `name` | строка | `= != in ~` | Отображаемое имя сервера в подписке. |
| `provider` | строка | `= != in ~` | Провайдер (подписка), предоставляющий сервер. |
| `type` | строка | `= != in ~` | Тип протокола, например `vless`, `trojan`, `ss`. |
| `server` | строка | `= != in ~` | Адрес сервера, к которому подключается узел. |
| `country` | строка | `= != in ~` | Подтверждённая страна выхода либо страна, определённая по имени. Значение никогда не бывает неизвестным. |
| `exit.country` | строка | `= != in ~` | Только подтверждённая страна выхода. До проверки неизвестна. |
| `entry.country` | строка | `= != in ~` | Страна, в которой расположен адрес самого сервера. Неизвестна, пока не определена. |
| `udp` | логическое | без оператора | Узел поддерживает UDP. |
| `alive` | логическое | без оператора | Недавно работал. |
| `dead` | логическое | без оператора | Подтверждённо недоступен. |
| `measured` | логическое | без оператора | В этой сети есть хотя бы один замер задержки. |
| `current` | логическое | без оператора | Сейчас выбран для группы. |
| `latency` | число | `= != < <= > >=` | Медианная задержка в мс. Для неизмеренного сервера условие ложно. |

### Поля страны

Страна задаётся **кодом ISO 3166-1 alpha-2**, например `NO`, `SE`, `DE`, `RU`. Используйте код, а не название: `country = SE`, а не `country = Sweden`.

Три поля страны отличаются источником данных.

| Поле | Источник | Когда значение неизвестно |
| --- | --- | --- |
| `country` | Подтверждённая движком страна выхода; если её нет — страна, определённая по **имени** сервера. | Никогда. Если значение не найдено, оно пустое (известно, что страна не определена), поэтому проверка не запускается. |
| `exit.country` | Только подтверждённая страна выхода. | Пока движок не подтвердит её по достаточному числу источников. |
| `entry.country` | Страна адреса сервера. | Пока адрес не определён. |

Страна из имени определяется в таком порядке: эмодзи-флаг; заглавный двухбуквенный код как отдельное слово (`DE`, `[NO]`); английское название страны или псевдоним (`Germany`, `USA`, `UK`, `Korea`, `Russian Federation`). Если найдено несколько подсказок, побеждает первое правило.

Для обычного выбора по расположению используйте `country`. Используйте `exit.country`, если важно фактическое место выхода трафика, например чтобы исключить выходы в собственной стране. Движок проверяет только серверы, нужные для принятия решения (см. [неизвестные и ожидающие значения](#трёхзначная-логика-неизвестные-и-ожидающие-значения)).

### Результаты проверок и метки

| Форма | Значение |
| --- | --- |
| `passes(id)` | Проверка `id` из профиля пройдена. |
| `fails(id)` | Проверка `id` завершилась подтверждённой ошибкой. |
| `tag(name)` | Условие с именем `name` из `tags` истинно. |

В черновике спецификации v2 упоминалось поле `group`, но такого поля нет. Поля сети и диагностика описаны в разделе [Условия сети](#условия-сети).

## Операторы

### Строки

| Оператор | Пример | Значение |
| --- | --- | --- |
| `=` | `country = NO` | Равно, без учёта регистра. |
| `!=` | `type != ss` | Не равно. |
| `in [ ]` | `country in [NO, SE]` | Равно одному из перечисленных значений. |
| `~` | `name ~ /gold|silver/` | Совпадение с регулярным выражением (поиск в любой части строки). |

### Числа

Операторы `= != < <= > >=`, необязательный суффикс `ms`: `latency <= 150ms` и `latency <= 150` означают одно и то же.

### Логические поля

Логическое поле записывается само по себе: `udp`, `not dead`, `alive and udp`. Не пишите `dead = true`.

### Логические связки

`and`, `or`, `not`, скобки. `not` перед проверкой инвертирует её: `not name ~ /test/`.

## Регулярные выражения

Оператор `~` использует синтаксис **RE2** языка Go. Просмотр вперёд/назад и обратные ссылки не поддерживаются; время сопоставления линейное.

Доступны две формы:

- `/pattern/` с необязательным флагом `i` для поиска без учёта регистра: `name ~ /gold/i` (то же, что `/(?i)gold/`). Другие флаги вызывают ошибку.
- Строка в кавычках: `name ~ 'gold|silver'`.

Чтобы включить буквальную косую черту в `/ /`, пишите `\/`. Длина шаблона — не более 512 символов.

### Экранирование в YAML

Сначала условие обрабатывает YAML, поэтому учитывайте правила YAML.

| Что нужно | Как записать |
| --- | --- |
| Буквальный `*` в имени | `name ~ /\*/` (обратная косая черта экранирует символ для регулярного выражения; обычный скаляр подходит) |
| Буквальный `|` или `.` | `\|` или `\.` в регулярном выражении |
| Регулярное выражение с `: ` или `#` | Заключить всё условие в одинарные кавычки |
| Одинарная кавычка внутри одинарных | Удвоить: `'it''s'` |
| Обратные косые черты в строке YAML с двойными кавычками | Удвоить: `"name ~ /\\*/"` |

В скалярах YAML с одинарными кавычками обратные косые черты сохраняются без изменений — это самый безопасный вариант: `when: 'name ~ /\*/ and not dead'`.

```yaml
rcx: 1
title: Starred and flagged
prefer:
  - label: Starred
    when: 'name ~ /\*/ and not dead'
  - label: Flag emoji
    when: 'name ~ /🇩🇪|🇳🇱/'
  - label: Anything
    when: not dead
```

## Функции

| Функция | Результат |
| --- | --- |
| `tag(name)` | Истинно, если условие этой метки истинно для сервера. Результат всегда известен. Внутри меток нельзя вызывать `tag()`. |
| `passes(id)` | Истинно, если проверка `id` пройдена. До измерения результат неизвестен. |
| `fails(id)` | Истинно, если проверка `id` завершилась ошибкой. До измерения результат неизвестен. |

Необязательная проверка с ошибкой считается *мягкой*: для неё и `passes`, и `fails` дают ложь.

## Трёхзначная логика: неизвестные и ожидающие значения

Неизмеренный движком факт не является ложью — он **неизвестен**. Поэтому у условий три результата: да, нет и неизвестно; они объединяются по логике Клини.

| `and` | да | нет | неизвестно |
| --- | --- | --- | --- |
| **да** | да | нет | неизвестно |
| **нет** | нет | нет | нет |
| **неизвестно** | неизвестно | нет | неизвестно |

| `or` | да | нет | неизвестно |
| --- | --- | --- | --- |
| **да** | да | да | да |
| **нет** | да | нет | неизвестно |
| **неизвестно** | да | неизвестно | неизвестно |

`not unknown` остаётся неизвестным.

На практике это означает следующее.

- **Шаг определяется только при известном результате.** Если условие сервера для шага 1 неизвестно, сервер считается **ожидающим**: возможно, он подходит для шага 1, но движку пока не хватает данных.
- **Ожидание запускает проверку.** Планировщик в рамках лимита ресурсов получает недостающее измерение (проверяет страну выхода или выполняет указанную проверку). Когда факт станет известен, сервер попадёт на соответствующий шаг.
- **Короткое вычисление экономит ресурсы.** `no and unknown` даёт *no*, поэтому сервер, уже не подходящий по `country = NO`, не вызовет проверку страны выхода в `country = NO and exit.country = NO`. Сначала указывайте дешёвые, всегда известные проверки.
- **Неизвестный результат в условиях пула разрешает сервер.** Сервер не исключается только из-за отсутствия данных.
- **Неизвестными бывают только конкретные поля**: `exit.country`, `entry.country` и `passes()`/`fails()` до измерения. `country`, `name`, `type`, `provider`, `server`, `udp` и `tag()` всегда известны. Условие `latency` для неизмеренного сервера ложно, а не неизвестно, поэтому само по себе не запускает проверку.
- Если ни один шаг не подошёл, но какой-либо шаг остался в ожидании, сервер отображается как «ожидающий», а не «без шага».

## Условия сети

Условия в `network.kinds` и `direct-split` описывают **сеть**, а не сервер. Допустимы такие поля:

| Поле | Тип | Значение |
| --- | --- | --- |
| `network.kind` | строка | Тип сети, определённый для группы. |
| `network.transport` | строка | Тип подключения, сообщаемый платформой; тесты используют `wifi`, `cellular` и `ethernet`. |
| `network.portal` | логическое | Обнаружена ли captive portal. |
| `metered` | логическое | Помечена ли сеть как тарифицируемая. |
| `<name> ok`, `<name> fail` | диагностика | Результат диагностики с таким именем из `network.diagnose`. |

Диагностика существует только в условиях сети. Поля серверов там недопустимы. Результат неизмеренной диагностики неизвестен, поэтому тип сети не определяется до завершения проверки.

```yaml
rcx: 1
title: Network kinds
network:
  diagnose:
    home: { tcp: ['77.88.8.8:443'] }
    foreign: { tls: ['1.1.1.1:443'] }
  kinds:
    - { kind: portal, when: network.portal, pause: true }
    - { kind: cell, when: network.transport = cellular and metered }
    - { kind: whitelist, when: 'home ok and foreign fail' }
prefer:
  - label: Anything
    when: not dead
```

## Примеры: от простых к сложным

Каждая строка — условие `when` или `pool`.

| Цель | Условие |
| --- | --- |
| Любой работающий сервер | `not dead` |
| Только Норвегия | `country = NO` |
| Не Россия | `country != RU` |
| Одна из нескольких стран | `country in [NO, SE, FI]` |
| В имени есть «Premium» (без учёта регистра) | `name ~ /premium/i` |
| В имени есть звёздочка | `name ~ /\*/` |
| В имени есть молния | `name ~ /⚡/` |
| Исключить демонстрационные серверы | `not name ~ /(?i)demo|test/` |
| Поддерживает UDP и быстрый | `udp and latency < 100` |
| Только Hysteria или TUIC | `type in [hysteria, hysteria2, tuic]` |
| От одного провайдера | `provider = MyProvider` |
| Не текущий сервер | `not current` |
| Быстрая Норвегия, иначе любая северная страна | два шага: `country = NO and latency < 80`, затем `country in [NO, SE, FI, DK]` |
| Проверенный выход не в моей стране | `exit.country != RU` |
| Проходит указанную проверку за рубежом | `passes(open) and exit.country != RU` |
| Метка или имя | `tag(bypass) or name ~ /(?i)lte/` |
| Есть звёздочка, страна NO или SE | `name ~ /\*/ and (country = NO or country = SE)` |

Более сложный пример целиком:

```yaml
rcx: 1
title: Careful ladder
level: advanced
tags:
  star: 'name ~ /\*/'
checks:
  open: { http: 'https://www.youtube.com/generate_204', expect: [204] }
pool:
  exclude: name ~ /(?i)test|demo/
prefer:
  - label: Starred, opens video, fast
    when: 'tag(star) and passes(open) and latency < 150'
  - label: Starred
    when: 'tag(star) and not dead'
  - label: Nordic, opens video
    when: 'country in [NO, SE, FI] and passes(open)'
  - label: Anything
    when: not dead
```

Чтение примера: для первого шага нужны сервер со звёздочкой, доступ к видео и небольшая задержка. Если проверка `open` ещё не выполнялась, сервер ожидает на шаге 1, поэтому планировщик запустит проверку. Если подходящего сервера нет, второй шаг выберет любой сервер со звёздочкой и так далее.

## Ограничения

| Ограничение | Значение |
| --- | --- |
| Длина условия | 2048 символов |
| Глубина вложенности | 16 |
| Длина регулярного выражения | 512 символов |

Опубликованная JSON-схема использует тот же лимит в 2048 символов.

Сообщение об ошибке указывает недопустимую часть и её позицию, например `unknown field "bogus"`. В студии ошибка показывается под соответствующей строкой.
