# Обмен

Пакеты, экспорт и импорт, ссылки `reclash://routing`, доставка от провайдера, согласие, rcxlint и JSON-схема.

## Пакеты

Пакет несёт профиль или сценарий и невстроенные профили, которые им нужны. Лимит: 256 КиБ.

```yaml title="split-bundle.rcx.yaml"
rcx: 1
kind: bundle
title: Split with Norway
scenarios:
  split-with-norway:
    rcx: 1
    title: Split with Norway
    groups:
      $main: { profile: user/norway }
profiles:
  norway:
    rcx: 1
    title: Norway
    prefer:
      - { label: Norway, when: 'country = NO' }
      - { label: Any, when: 'not dead', last-resort: true }
```

| Ключ | Описание |
| --- | --- |
| `kind: bundle` | Помечает пакет; без него файл — один профиль или сценарий. |
| `title` | Название главного элемента. |
| `scenarios` | Имя → сценарий. |
| `profiles` | Имя → профиль. |

Пакету нужен хотя бы один профиль или сценарий (`bundle holds no profiles or scenarios`); каждая запись должна быть
отображением. В пакете `user/<key>` ссылается на собственный профиль пакета `<key>`.

Без `kind: bundle` файл — сценарий, если у него есть ключ верхнего уровня `groups`, `mode` или `routes`; иначе профиль.

## Экспорт

Экспорт начинается с записи библиотеки. Если запись ссылается только на встроенные профили, экспортируется простой документ.
Иначе создаётся пакет с элементом и всеми профилями, достижимыми через `extends`, `profile` в программах,
`on.<kind>.groups` или маршруты, на любую глубину.

Имена в пакете берутся из названий: строчными буквами, каждая последовательность символов вне `a-z0-9` заменяется на `-`,
края обрезаются, при совпадении добавляется `-2`, `-3`, …; пустой результат заменяется последним сегментом id. Ссылки
переписываются в `user/<name>`.

| Формат | Содержимое |
| --- | --- |
| **Экспорт в буфер обмена** | Текст YAML. |
| **Копировать ссылку** | Ссылка `reclash://routing?p=…`. |
| **Экспорт файла** | `<name>.rcx.yaml`. |

## Импорт

Импорт принимает файл, буфер обмена или ссылку. Проверка показывает ошибки, предупреждения, узлы, к которым обратится импорт,
и что профиль выбрал бы сейчас в выбранной группе; для проверки нужно запущенное ядро. **Добавить в библиотеку** сохраняет
каждый элемент как профиль или сценарий пользователя; ничего не запускается.

Отдельные документы получают имя из названия. Элементы пакета получают имена из ключей, профили первыми, в обход занятых
имён; ссылки `user/<key>` переписываются на сохранённые имена. Импорт никогда не заменяет существующую запись.

## Ссылки

| Форма | Содержимое |
| --- | --- |
| `reclash://routing?p=<payload>` | Документ, сжатый raw DEFLATE и закодированный в base64url без выравнивания. Полезная нагрузка — до 128 КиБ, раскодированный текст — до 64 КиБ. |
| `reclash://routing?url=https://…` | Приложение загружает документ по URL HTTPS; до 64 КиБ. |

Ссылка несёт ровно один из `p` или `url`, без пути и фрагмента. Открытие ссылки запускает проверку импорта.

## Доставка от провайдера

Подписка раздаёт RCX одним из двух каналов. Объявленное в файле подписки важнее пакета.

| Канал | Содержимое |
| --- | --- |
| Конфиг подписки | Привязки `rcx:` в `proxy-groups`, ключи верхнего уровня `rcx-profiles`, `rcx-scenarios` и `rcx-scenario`. |
| Пакет маршрутизации | Файл YAML по URL из поля подписки `reclash-routing`, с `profiles`, `groups` (привязки по именам групп), `scenarios` и `scenario`; до 256 КиБ. |

Профили и сценарии провайдера получают id `provider/<name>`. Синтаксис полей и подробности доставки — в разделе
[Доставка маршрутизации](../providers/routing.md).

## Согласие

Профиль или сценарий провайдера может обращаться к узлам через проверки, диагностики и эхо-сервисы. Без вопроса разрешены:

- эхо-сервисы по умолчанию и все адреса встроенных профилей;
- регистрируемый домен провайдера из URL подписки и URL пакета маршрутизации;
- узлы, которые пользователь уже разрешил для этой подписки.

Любой другой узел придерживает элемент, пока пользователь его не разрешит; проблема `profile.consent` перечисляет эти узлы.
Группа с таким профилем работает на `builtin/simple`; такой сценарий не управляет ни одной группой. Для профиля проверяется
каждая запись провайдера в цепочке `extends`. Профилям и сценариям пользователя согласие не нужно.

## rcxlint

`rcxlint` проверяет профили, сценарии и пакеты той же валидацией, что и приложение.

```sh
cd core
go run ./rcx/cmd/rcxlint profile.rcx.yaml scenario.rcx.yaml
dart run tool/rcx.dart lint profile.rcx.yaml
```

| Вход | Признак | Проверяется как |
| --- | --- | --- |
| Пакет обмена | `kind: bundle` | Его профили как `user/<key>` |
| Пакет провайдера | `profiles` или `scenarios` верхнего уровня | `provider/<name>`; также проверяется, что `scenario`, а также `default` и `profiles` каждой группы определены |
| Сценарий | `groups`, `routes` или `mode` верхнего уровня | `provider/<имя файла>` |
| Профиль | Всё остальное | `provider/<имя файла>` |

Из имени файла отбрасываются `.yaml` и `.rcx`. Строки вывода:

```text
file:line: error: [profile X: | scenario X: ]message
file:line: warning: [profile X: | scenario X: ]message
file: note: [profile X: ]contacts third-party host H (use); the user must allow it
```

Код выхода: 0 без ошибок, 1 при любой ошибке, 2 при неверном использовании.

### Предупреждения

| Предупреждение | Смысл |
| --- | --- |
| `tag X is never used` | Ни одно условие не ссылается на тег. |
| `check X is never used, so it never runs` | Ни одно условие не ссылается на проверку. |
| `tier A repeats the condition of B, so nothing lands in it` | У двух уровней одно условие; второй недостижим. |
| `the pool admits no server of G` | В приложении, против работающей группы. |
| `no server of G is in T right now` | В приложении, против работающей группы. |
| `this config has no group G` | В приложении, для цели сценария. |

## JSON-схема

`rcx-profile.schema.json` в корне репозитория проверяет профиль на верхнем уровне; `$defs.scenario` и `$defs.bundle` описывают
остальные документы. Схема проверяет структуру и форму значений, но не условия.

```json title=".vscode/settings.json"
{
  "yaml.schemas": {
    "./rcx-profile.schema.json": "*.rcx.yaml"
  }
}
```
