## Пакеты

**Пакет** — один YAML-файл с несколькими профилями и сценариями. Он нужен, потому что сценарий обычно ссылается на профили и без них бесполезен на другом устройстве.

```yaml
rcx: 1
kind: bundle
title: Streaming
scenarios:
  streaming:
    rcx: 1
    title: Streaming
    groups:
      $main: { profile: user/streaming-fast }
profiles:
  streaming-fast:
    rcx: 1
    title: Streaming fast
    extends: builtin/fastest
    prefer:
      - label: Germany
        when: country = DE
      - label: Anything
        when: not dead
```

| Ключ | Значение |
| --- | --- |
| `rcx` | Версия формата: `1`. |
| `kind: bundle` | Помечает документ как пакет. Без этого ключа файл считается одним профилем или сценарием. |
| `title` | Отображается при импорте. |
| `scenarios` | Карта «имя → сценарий». |
| `profiles` | Карта «имя → профиль». |

Пакет должен быть в UTF-8 и иметь размер не более 256 КиБ. В нём должен быть хотя бы один профиль или сценарий; каждая запись должна быть объектом.

Приложение при экспорте именует профили пакета как `user/<name>`; `rcxlint` и проверка импорта проверяют пакет именно в таком виде.

## Экспорт

Экспорт профиля или сценария создаёт:

- сам документ, если ему нужны только встроенные профили;
- иначе пакет со всеми невстроенными профилями, на которые он ссылается прямо или косвенно, включая ссылки через `extends` и программы на любой глубине.

При экспорте ссылки переписываются. Каждый невстроенный профиль в цепочке зависимостей становится *пользовательским* профилем с именем из его заголовка (строчные буквы, последовательности остальных символов заменяются на `-`), а ссылки в экспортируемых документах меняются на `user/<new-name>`. Ссылки `builtin/...` остаются без изменений. При совпадении имени добавляется числовой суффикс (`-2`, `-3`).

Это гарантия **пакета**: экспортируемая настройка содержит все невстроенные профили, на которые она ссылается.

## Импорт и распаковка

При чтении документа приложение сначала проверяет, является ли он пакетом (`kind: bundle`). Обычный профиль или сценарий импортируется как один элемент; его имя берётся из заголовка или, если заголовка нет, задаётся как `profile` либо `scenario`.

В пакете каждому элементу **назначается новое имя**, свободное в библиотеке пользователя. За основу берётся ключ пакета (строчные буквы, последовательности остальных символов заменяются на `-`); при необходимости добавляется числовой суффикс. Ссылки между элементами переписываются, чтобы импортированный сценарий ссылался на импортированные копии профилей.

Импорт никогда не заменяет уже существующий профиль пользователя: если `streaming-fast` уже есть, новый получит имя `streaming-fast-2`, а ссылка сценария обновится. Студия проверяет весь пакет с учётом профилей, которые появятся в библиотеке после такого импорта.

Проект v3 предусматривает тест полного цикла (экспорт, затем распаковка), который должен восстанавливать исходные документы.

## Доставка провайдером

Провайдер может включить профили и сценарии в подписку. Полное описание приведено в [PROVIDER_FEATURES.md](../PROVIDER_FEATURES.md); здесь — краткая версия.

### Профили

| Способ | Формат |
| --- | --- |
| Встроенный | Верхнеуровневый `rcx-profiles: {name: profile}` в YAML подписки, а для каждой группы `select` — `rcx: {profiles: [...], default: name, chips: [{label, include}]}`. Обычный mihomo игнорирует оба поля. |
| Пакет | Заголовок ответа `reclash-routing: <https url>` либо строка-комментарий `#reclash-routing: <url>` в теле. Пакет `{rcx: 1, profiles, groups, scenarios, scenario}` имеет размер не более 256 КиБ и привязывается к группам по имени. |

Встроенные объявления подписки имеют приоритет над пакетом. Профили провайдера адресуются как `provider/<name>`; `extends` может ссылаться на `builtin/<name>` или другой профиль провайдера. Провайдер может только сужать пул группы и не может включать `direct-split`. Для подключения к узлам за пределами сайта провайдера требуется [согласие пользователя](engine.md#согласие-для-профилей-провайдера).

```yaml
# фрагмент подписки (proxy-группы опущены)
rcx-profiles:
  fast-de:
    rcx: 1
    title: Fast Germany
    prefer:
      - { label: Germany, when: 'country = DE' }
      - { label: Anything, when: 'not dead' }
proxy-groups:
  - name: Proxy
    type: select
    include-all: true
    rcx: { profiles: [fast-de], default: fast-de }
```

### Сценарии

| Способ | Формат |
| --- | --- |
| Встроенный | Верхнеуровневые `rcx-scenarios: {name: scenario}` и `rcx-scenario: <name>` (сценарий по умолчанию). |
| Пакет | `scenarios: {name: scenario}` и `scenario: <name>`. |

Встроенные объявления имеют приоритет над пакетом. Пользователь выбирает сценарий или отключает автоматическое управление. Сценарий провайдера с диагностикой сторонних узлов требует согласия.

```yaml
# фрагмент подписки (proxy-группы опущены)
rcx-scenarios:
  work:
    rcx: 1
    title: Work
    description: Everything via Germany, internal sites direct.
    groups:
      $main: { profile: builtin/fastest }
    routes:
      - name: Intranet
        match: [DOMAIN-SUFFIX,corp.example]
        to: DIRECT
rcx-scenario: work
```

Полный пакет доставки, который проходит проверку `rcxlint` без изменений:

```yaml
rcx: 1
profiles:
  fast-de:
    rcx: 1
    title: Fast Germany
    prefer:
      - label: Germany
        when: country = DE
      - label: Anything
        when: not dead
scenarios:
  work:
    rcx: 1
    title: Work
    description: Everything via Germany, internal sites direct.
    groups:
      $main: { profile: provider/fast-de }
    routes:
      - name: Intranet
        match: [DOMAIN-SUFFIX,corp.example]
        to: DIRECT
scenario: work
```

## Ссылки rcx

Ссылкой можно поделиться в чате, отправив профиль или сценарий. Формат задаётся в `lib/common/rcx_link.dart` и `lib/common/url_scheme.dart`.

```text
reclash://routing?p=<payload>
reclash://routing?url=<https url>
```

- Параметр `p` содержит YAML: текст UTF-8 сжимается raw deflate (уровень 9), затем кодируется в base64url без дополнения. Распакованный текст ограничен 64 КиБ; ограничение проверяется во время распаковки, чтобы небольшой архив не развернулся в огромный файл.
- `url` — адрес `https://` файла с документом. Размер загруженного файла не должен превышать 64 КиБ.
- Ссылка должна содержать ровно один параметр: `p` или `url`. Любые другие элементы (путь, фрагмент, дополнительные параметры) приводят к отказу как от некорректной ссылки.
- Ссылку можно вставить и в поле импорта; приложение декодирует её перед чтением текста.

Ссылка открывает экран проверки импорта, а не библиотеку: перед сохранением пользователь видит результат проверки и запрос согласия.

## JSON-схема и редакторы

Файл `rcx-profile.schema.json` в корне репозитория описывает профиль (в корне схемы) и пакет (в `$defs.bundle`). Схема соответствует JSON Schema 2020-12; тест сверяет её с `core/rcx/profile.go` по наборам ключей.

Чтобы включить автодополнение и подсветку ошибок в редакторе с поддержкой YAML-схем (например, VS Code с расширением YAML), привяжите схему к файлам. В настройках VS Code:

```json
{
  "yaml.schemas": {
    "./rcx-profile.schema.json": "*.rcx.yaml"
  }
}
```

Два замечания:

- Схема проверяет структуру и форму значений. Она не разбирает условия, а только ограничивает их длину 2048 символами — как и приложение.
- Схема описывает профили и пакеты; сценарии нужно проверять с помощью `rcxlint`.

## Инструмент rcxlint

`rcxlint` проверяет файлы так же, как приложение при импорте: тем же парсером, с теми же ограничениями и сообщениями с номерами строк.

```text
cd core
go run ./rcx/cmd/rcxlint <file.yaml>...
```

Или из корня репозитория:

```text
dart run tool/rcx.dart lint <file.yaml>...
```

Инструмент автоматически распознаёт три вида файлов:

| Файл | Признак |
| --- | --- |
| Пакет | Верхнеуровневый ключ `profiles` или `scenarios` |
| Сценарий | Верхнеуровневый ключ `groups`, `routes` или `mode` |
| Профиль | Любой другой файл |

Для обычного файла используется ID `provider/<file name>`. Файл с `kind: bundle` проверяется так, как приложение импортирует его: профили получают имена `user/<name>`. Для пакета провайдера без `kind` профили получают имена `provider/<name>`; кроме того, инструмент проверяет, что сценарий по умолчанию существует и каждая привязка группы ссылается на определённый профиль.

Код завершения 0 означает отсутствие ошибок, 1 — наличие хотя бы одной ошибки, 2 — неверное использование. Для каждой проблемы выводится отдельная строка:

```text
bad.yaml:3: error: prefer 1 (): unknown field "bogus"
profiles.yaml: warning: profile provider/p contacts example.com; allow them first
```

Предупреждения (например, о неиспользуемой проверке или узлах, требующих согласия) не приводят к ошибке запуска. Поскольку проверяется форма провайдера, для профиля, обращающегося к сторонним узлам, всегда выводится предупреждение о согласии; это ожидаемо, а решение при импорте принимает пользователь.
