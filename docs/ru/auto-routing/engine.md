# Движок

Как RCX собирает свидетельства, распознаёт сети, принимает решения, переключается и тратит пробы, с точными правилами и значениями по умолчанию.

## Свидетельства

Свидетельства хранятся по серверу и по сетевому окружению (Wi-Fi, оператор или шлюз, хешированные с солью установки).
Хранится не больше 16 окружений; вытесняется наименее недавно использованное.

| Факт | Правило |
| --- | --- |
| Замеры задержки | Последние 8 за 6 часов. `p50` — медиана; разброс — `p90 − p50`. |
| Эпизоды | Эпизоды сбоев за последние 24 часа, не больше 16. |
| Свежесть | Успех свеж 45 минут или 3 часа, когда окружению 2 часа. |
| Результаты проверок | Хранятся 6 часов. Прохождение отменяет только второй сбой подряд; один сбой после прохождения делает результат неизвестным. |
| Страна выхода | Глобально для сервера, 24 часа. Несогласованный поиск повторяется через 2 часа. |
| Сбои соединения | 3 неудачных соединения за 20 секунд без успеха между ними делают сервер подозрительным. |

Источники: пробы движка, URL-тесты mihomo и реальный трафик, который считается успехом.

### Здоровье

| Здоровье | Условие |
| --- | --- |
| `dead` | Помечен мёртвым, и успеха с тех пор не было. |
| `alive` | Свежий успех и ни одного сбоя после него. |
| `stale` | Успех есть, но не свежий, или после него был сбой. |
| `unknown` | Успехов не было. |

### Оценка

| `rank.by` | Оценка |
| --- | --- |
| `latency` | `p50 + spread/2 + 50 × episodes` |
| `stability` | `p50 + spread + 300 × episodes` |

Неизмеренный сервер получает 2²⁰. Меньше — лучше.

### Страна выхода

Эхо-сервисы опрашиваются через сервер по одному, пока ответ не установится; каждый узел сервиса — один голос. Локальный
поиск GeoIP по сообщённому адресу добавляет ещё один голос. Страна принимается, только когда все действительные голоса
называют её и проголосовало не меньше `agree` разных источников (по умолчанию 2). `XX`, `T1` и `EU` отвергаются; до
этого `exit.country` неизвестна. Эхо-сервисы по умолчанию: `https://www.cloudflare.com/cdn-cgi/trace` и
`https://ipinfo.io/json`.

## Типы сетей

Профиль или сценарий объявляет типы упорядоченным списком правил над сетевыми условиями и прямыми диагностиками.

- Тип называет первое правило с истинным условием; неизвестное правило оставляет тип нерешённым.
- Переход от отсутствия типа к типу применяется сразу. Переход между типами или обратно к отсутствию требует 2 согласных раундов.
- Тип запоминается по окружению, отдельно для каждого профиля и для сценария.
- `pause: true` держит группу (`hold.paused`) и останавливает её проверки, пока тип активен.
- Диагностики общие для всех групп и сценария, без повторов по целям, и повторяются через 5, 10, затем 30 минут.

## Решение

Решение для группы принимается при каждом изменении политики, свидетельств или контекста. Оно — чистая функция от них:
его объяснение — ранжирование, по которому оно принято; ввод-вывод оно никогда не выполняет.

### Пригодность

Каждый элемент проверяется в этом порядке; первое совпадение исключает его.

| Код | Исключён, когда |
| --- | --- |
| `pool.no-match` | `pool.include` ложно (неизвестное допускает). |
| `pool.excluded` | `pool.exclude` истинно. |
| `pool.unroutable` | Элемент — `REJECT`, `REJECT-DROP`, `PASS`, `COMPATIBLE`, `DIRECT` или `DNS`. |
| `cooldown` | Его покинули через **Сменить сервер** меньше 15 минут назад. |
| `dead` | Его здоровье — `dead`. |
| `pending` | Ни один уровень ещё не истинен, но один неизвестен; записывается первый неизвестный уровень. |
| `no-tier` | Все уровни ложны. |

Пригодный элемент получает первый уровень с истинным условием. Запасные уровни сортируются после всех остальных, где бы
они ни стояли.

### Ранжирование

Элементы сортируются так: сначала пригодные, затем уровень, здоровье (`alive`, `stale`, `unknown`, `dead`),
эффективная оценка, имя. Эффективная оценка текущего элемента — его оценка минус `rank.tolerance`, если он измерен.
Первая строка — лучший кандидат. До 2 элементов `pending`, чей неизвестный уровень лучше уровня лучшего кандидата,
ставятся в очередь на проверку при каждом решении.

### Порядок

1. Управление `manual`: действие `manual`, больше ничего не выполняется.
2. Элемент `to` сценария, если нет закрепления: `hold.fixed`, `switch.fixed` или `fixed.missing`, который держит текущий элемент.
3. Тип сети с `pause`: `hold.paused`.
4. Закрепление, если закреплённый элемент есть, не мёртв и не исключён: `hold.pinned` или `switch.pinned`. Иначе
   закрепление ждёт, а закреплённый элемент ставится в очередь на проверку.
5. Нет лучшего кандидата: `hold.no-alternative`, если текущий элемент в паузе после смены, иначе `stranded`.
6. Правила переключения ниже.

### Переключение

| Шаг | Условие | Результат |
| --- | --- | --- |
| 1 | Нет текущего элемента | `switch.initial` |
| 2 | Запрошено **Сменить сервер**, и лучший — другой элемент | `switch.change-server` |
| 3 | Текущий элемент мёртв | `switch.failover`; его соединения закрываются |
| 4 | Текущий элемент исключён по любой причине, кроме паузы после смены | `switch.out-of-pool` |
| 5 | Текущий элемент в паузе после смены, и альтернативы нет | `hold.no-alternative` |
| 6 | Лучший — текущий элемент | `hold.best` |
| 7 | Лучший — на лучшем уровне | `switch.better-tier`, если он `alive` и проверен за последние 5 минут; иначе `hold.checking` до проверки |
| 8 | `improve: false` | `hold.working` |
| 9 | Одна из сторон не измерена, или выигрыш в оценке меньше нужного | `hold.best` |
| 10 | Последнее переключение было в пределах `dwell` | `hold.dwell` |
| 11 | Достигнуто `max-per-hour` переключений | `hold.flap-limit` |
| 12 | Меньше `confirm` свежих замеров обгоняют текущий элемент на нужную величину | `hold.confirming` |
| 13 | Иначе | `switch.faster` |

Нужная величина — `max(min-gain-ms, score × min-gain-pct / 100, tolerance)`, по оценке текущего элемента. `confirm`
считает последние подряд свежие замеры кандидата, которые не больше `current score − need`.

### Безвыходное положение

| `stranded` | Результат |
| --- | --- |
| `hold` (по умолчанию) | Оставить текущий элемент: `stranded.no-candidates`. |
| `direct` | Выбрать `DIRECT`: `switch.stranded`. |
| `group:<name>` | Выбрать элемент `<name>`, если он есть в группе: `switch.stranded`. |

### Наборы характера

| `feel` | `dwell` | `min-gain-ms` | `min-gain-pct` | `confirm` | `max-per-hour` |
| --- | --- | --- | --- | --- | --- |
| `calm` | 30m | 60 | 30 | 3 | 2 |
| `balanced` (по умолчанию) | 10m | 30 | 20 | 2 | 4 |
| `eager` | 2m | 15 | 10 | 2 | 8 |

Явные поля `switch` переопределяют набор.

## Пробы

Планировщик покупает только пробы, которые могут изменить решение. Одновременно идут не больше 2, у каждой таймаут 5 секунд.
Сервер не проверяется повторно в течение 1 минуты, кроме подтверждения сбоя.

### Режимы

Действует первый подходящий режим.

| Режим | Когда | Разрешено |
| --- | --- | --- |
| Остановлен | Ядро не запущено | Ничего |
| Сон | Android Doze | Ничего |
| Фон | Экран выключен | Восстановление, только после реальных сбоев соединения |
| Эко | Лимитная сеть, энергосбережение, низкий заряд или работа от батареи | Восстановление; нужды и обслуживание в пределах окна; принудительные диагностики |
| Активный | В течение 10 с после трафика или 30 с после смены сети | Всё, включая разведку |
| Простой | Иначе | Восстановление |

Окно открывается на 10 с при трафике и на 30 с при смене сети. Нуждам, обслуживанию и разведке нужны открытое окно и
10 секунд после пробуждения. Диагностики идут в режиме «Активный», а в «Эко» — после смены сети или пока тип ждёт
подтверждения.

### Бюджеты

`energy` каждой группы задаёт часовые корзины токенов. Машина берёт самый высокий уровень среди своих групп; любое
условие «Эко» включает `eco`.

| `energy` | Обслуживание | Разведка | Восстановление | Сеть | Проверка запасного раз в |
| --- | --- | --- | --- | --- | --- |
| `eco` | 4 | 0 | 12 | 8 | 2 ч |
| `balanced` (по умолчанию) | 10 | 12 | 24 | 12 | 45 мин |
| `precise` | 20 | 40 | 40 | 20 | 30 мин |

Каждый запрос считается как 6 КиБ при суточном лимите 20 МиБ. Превысить лимит могут только проверки пользователя и
восстановление; проверки пользователя никогда не нормируются.

### Виды проб

| Вид | Что |
| --- | --- |
| Восстановление | Мёртвые или подозрительные серверы, по 4 за проход, с отсрочкой 0, 5, 10, 20, 40 минут. |
| Нужда | Элементы `pending`, закреплённый элемент или кандидат с лучшего уровня; оплачивается из корзины разведки. |
| Обслуживание | Два запасных, плюс текущий элемент, если профиль улучшает или использует проверки или страну выхода, раз в интервал проверки запасного. |
| Разведка | Два неизмеренных элемента за окно с разными адресами серверов; только с `improve: true` и в режиме «Активный». |
| Дополнения | Проверки и поиск выхода едут на успешной пробе, по одному запросу из той же корзины. |
| Пользователь | Действие `check`: каждый маршрутизируемый элемент со всеми дополнениями. |

## Обработка сбоев

Сбои, замеченные, пока ничего не проходит, не обвиняют ни один сервер.

- Канал считается подтверждённым, если что-то удалось за последнюю минуту. Пробуждение или смена сети сбрасывает это.
- Неудачная проба помечает сервер мёртвым, только когда канал подтверждён и сервер не прошёл как минимум дважды подряд.
- Подозрительный текущий элемент подтверждается вместе с лучшим запасным. Если сбоят оба или нет запасного на
  неподтверждённом канале, журнал записывает `network.suspect`, и сервер откладывается. Сбой только текущего элемента
  помечает его мёртвым (`failure.confirmed`), что вызывает `switch.failover`.

## Прямой обход

Пока он активен, соединения, совпавшие с явным правилом `DIRECT`, идут через группу.

- Нужны и условие `direct-split` профиля, и переключатель пользователя на группе; подписка включить его не может.
- Никогда не действует на последнее правило `MATCH` и на локальные адреса: частные, loopback, link-local, multicast,
  unspecified, `100.64.0.0/10` и имена, которые разрешаются только в локальной сети. UDP обходит, только если элемент
  группы поддерживает UDP.
- Состояние группы: выключено, ожидание (ядро остановлено, нет элементов, ручное управление, тип сети на паузе или
  условие не истинно) или активно. Трафик берёт первая активная группа по порядку. Переходы пишутся в журнал как
  `split.on` и `split.off`.

## Управление

| Действие | Эффект |
| --- | --- |
| Авто | Решение принимается как выше; снимает закрепление. |
| Закрепить | Держит выбранный элемент, пока он работает, и возвращается к нему после восстановления. Ядро умеет ограничить закрепление текущей сетью; приложение закрепляет во всех сетях. |
| Вручную | Движок никогда не переключает и не проверяет; проверки здоровья провайдера не подавляются. |
| Сменить сервер | Ставит текущий элемент на 15-минутную паузу, снимает закрепление и вызывает переключение. |
| Проверить | Одна проба из корзины пользователя для каждого маршрутизируемого элемента. Ядро принимает её; приложение не предлагает. |

Ручной выбор сервера в списке прокси закрепляет его (`pin.manual` в журнале), если группа не в режиме «Вручную». Пока
группа умная, не в ручном режиме и не простаивает, движок заменяет автоматическую проверку здоровья каждого провайдера,
который обслуживает её элементы.

## Объяснения и журнал

**Почему этот сервер** возвращает решение: действие, цель, причину, уровень, время окончания удержания (`until`) и полное
ранжирование. Каждая строка содержит имя, уровень и метку, здоровье, задержку, разброс, оценку, эпизоды, последнюю
проверку, признак текущего, причину исключения, страну выхода, результаты проверок (pass, fail, soft) и ожидающий уровень.

Журнал хранит последние 200 записей видов `switch`, `stranded`, `change`, `pin`, `auto`, `manual`, `network`, `mode`,
`split` и `failure`. Он сохраняется вместе с состоянием движка, не больше 1 МиБ.

## Гарантии

| Гарантия | Формулировка |
| --- | --- |
| Слои | Слои провайдера и пользователя только сужают пул профиля; неверный профиль или непригодная группа — видимая проблема. |
| Согласие | Профиль провайдера обращается к сторонним узлам только после разрешения пользователя; до тех пор группа работает на `builtin/simple` и объясняет почему. |
| Лестница | Порядок проваливается дальше, когда все серверы шага недоступны; запасной шаг уступает всем остальным; порядок программы сценария важнее пользовательского, а тот — порядка профиля. |
| Сценарий | Сценарий задаёт режим туннеля, только пока пользователь не выбрал режим сам, и управляет только названными группами. |
| Маршруты | Маршруты становятся группами и правилами только при применении конфига, направляют трафик только в режиме правил, никогда не захватывают существующую группу, а неприменимый маршрут — видимая проблема. |
| Пакет | Экспорт несёт каждый невстроенный профиль, на который ссылается; импорт никогда не заменяет профиль, который у пользователя уже есть. |
| Тонкий форк | Форк mihomo несёт подавление проверок здоровья провайдера, отпечатки маршрутов и хуки прямого обхода плюс минимальные защитные хуки; толкование политики остаётся в ядре ReClash. |
