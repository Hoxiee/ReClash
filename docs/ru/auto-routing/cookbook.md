# Сборник примеров

Практические рецепты. Для каждого приведены цель, полный YAML, разбор по строкам и результат в приложении. Все блоки YAML проходят [`rcxlint`](sharing.md#инструмент-rcxlint), если не указано иное. Чтобы использовать сценарий, импортируйте его (см. [Обмен](sharing.md)) и выберите в центре маршрутизации; чтобы использовать профиль, назначьте его группе.

В примерах предполагается, что в именах серверов есть флаг или код страны, как в большинстве подписок. Если у вас это не так, используйте условия `name ~ /.../` вместо `country`.

## 1. Норвегия для основного трафика и отдельные серверы для сервисов

**Цель.** Весь трафик идёт через Норвегию. YouTube предпочитает российский сервер со значком молнии в имени, затем любой российский, затем любой сервер. Claude идёт через Швецию. Для Gemini используются серверы со `*` в имени. Сайты своей страны идут напрямую.

```yaml
rcx: 1
title: Daily routes
description: Norway for everything, with special servers for YouTube, Claude and Gemini.
groups:
  $main:
    prefer:
      - label: Norway
        when: country = NO
      - label: Anything
        when: not dead
routes:
  - name: YouTube
    match: [GEOSITE,youtube]
    prefer:
      - label: Fast Russian
        when: country = RU and name ~ /⚡/
      - label: Russia
        when: country = RU
      - label: Anything
        when: not dead
  - name: Claude
    match: [GEOSITE,anthropic, DOMAIN-SUFFIX,claude.ai]
    prefer:
      - label: Sweden
        when: country = SE
      - label: Anything
        when: not dead
  - name: Gemini
    match: [GEOSITE,google-gemini]
    prefer:
      - label: Starred
        when: name ~ /\*/
      - label: Anything
        when: not dead
  - name: Local
    match: [GEOSITE,category-ru, GEOSITE,yandex, GEOIP,RU,no-resolve]
    to: DIRECT
```

**Разбор по строкам.**

- `groups.$main` управляет группой, на которую направлено итоговое правило `MATCH`. В ней сначала выбираются серверы Норвегии, затем любые работающие.
- Каждый маршрут (`YouTube`, `Claude`, `Gemini`) создаёт отдельную группу `select` с `include-all`, видящую все серверы; собственный `prefer` маршрута задаёт порядок серверов. Правила маршрутов добавляются перед правилами конфигурации.
- `name ~ /⚡/` находит имена серверов со значком молнии; `country = RU` соответствует российским серверам (флаг или код в имени). `country = RU and name ~ /⚡/` означает «оба условия».
- Маршрут Claude содержит категорию и домен: `GEOSITE,anthropic` и `DOMAIN-SUFFIX,claude.ai`. Достаточно любого совпадения.
- Gemini использует `name ~ /\*/`: обратная косая черта означает, что `*` — буквальный символ регулярного выражения.
- Для маршрута `Local` задано `to: DIRECT`, поэтому группа не создаётся. Совпадения `category-ru`, `yandex` и `GEOIP,RU` (с `no-resolve`, чтобы правило не запускало DNS-запрос) отправляются напрямую.
- Порядок маршрутов важен: правила добавляются именно в нём, и выигрывает первое совпадение.

**Что увидите.** В центре маршрутизации сценарий содержит четыре маршрута. У каждого отображаются текущий сервер и шаг, который его выбрал. На экране прокси появляются три дополнительные группы: `YouTube`, `Claude` и `Gemini`. Маршруты действуют только в режиме rule; в режимах global и direct центр сообщает об этом.

> [!NOTE]
> **Снимок экрана `cookbook-routes-hub`** — центр сценариев с маршрутами YouTube, Claude, Gemini и Local; у каждого показаны текущий сервер и выбравший его шаг.

## 2. Лестница: сначала звёздочки, затем страна, потом любой сервер

**Цель.** Сначала серверы со `*` в имени, затем Финляндия, затем любой работающий сервер.

```yaml
rcx: 1
title: Starred, then Finland, then any
prefer:
  - label: Starred
    when: name ~ /\*/ and not dead
  - label: Finland
    when: country = FI
  - label: Anything
    when: not dead
    last-resort: true
```

**Разбор по строкам.**

- Шаг 1 `Starred`: `name ~ /\*/ and not dead` — в имени есть звёздочка, сервер не признан неисправным.
- Шаг 2 `Finland`: `country = FI` — имя указывает на Финляндию.
- Шаг 3 `Anything`: `not dead`, дополнительно помечен `last-resort: true`.
- Движок использует первый шаг, в котором есть работающий сервер. Если все серверы со звёздочкой не работают, используется шаг 2 и так далее. Внутри шага выбирается самый быстрый сервер.
- Замените `FI` кодом нужной страны. Используйте двухбуквенный код ISO, а не название: `country = FI`, не `country = Finland`.

`last-resort: true` оставляет `Anything` последним, даже если позднее после него добавят новый шаг (см. [Профили](profiles.md#prefer)).

**Что увидите.** Рейтинг объяснения группы разделён по шагам. Для текущего сервера указаны метка шага (`Starred`, `Finland` или `Anything`) и причина выбора.

> [!NOTE]
> **Снимок экрана `cookbook-ladder-ranking`** — рейтинг группы разбит по шагам Starred, Finland и Anything; текущий сервер отмечен.

## 3. Экономичный и стабильный профиль для слабого телефона

**Цель.** Мало проверок, редкие переключения, стабильный сервер.

```yaml
rcx: 1
title: Cheap and steady
description: For weak phones. Few checks, rare switches.
extends: builtin/stable
energy: eco
switch:
  feel: calm
  max-per-hour: 1
```

**Разбор по строкам.**

- `extends: builtin/stable` наследует стабильное поведение: ранжирование по стабильности, допуск 100, спокойные переключения.
- `energy: eco` разрешает 4 поддерживающие проверки в час, без обнаружения и 12 восстановительных проверок (см. [лимиты](engine.md#бюджеты)).
- `switch.feel: calm` вместе с `max-per-hour: 1` разрешает не более одного добровольного переключения в час. Неисправный сервер всё равно заменяется сразу.
- Больше ничего не требуется: при выключенном экране движок и так не проверяет серверы, если только реальный трафик не перестал проходить.

**Что увидите.** В центре маршрутизации отображается «Eco», а группа редко меняет сервер. В журнале мало записей.

## 4. Разное поведение в мобильной сети и Wi-Fi

**Цель.** Самый быстрый сервер по Wi-Fi и стабильный — при мобильной передаче данных.

```yaml
rcx: 1
title: Mobile vs Wi-Fi
description: Stable and frugal on mobile data, fastest on Wi-Fi.
network:
  kinds:
    - kind: cell
      when: network.transport = cellular
    - kind: wifi
      when: network.transport = wifi
groups:
  $main: { profile: builtin/fastest }
on:
  cell:
    groups:
      $main: { profile: builtin/stable }
```

**Разбор по строкам.**

- `network.kinds` определяет тип сети. Тип задаётся первым истинным условием: `cell` для сотовой сети и `wifi` для Wi-Fi.
- `groups.$main` по умолчанию назначает основной группе `builtin/fastest`.
- `on.cell.groups.$main` заменяет эту запись, когда тип сети — `cell`: используется `builtin/stable`.
- Для смены типа нужны два совпавших результата, поэтому кратковременное прохождение через туннель не переключит поведение.

**Что увидите.** В статусе сценария указан тип сети (`cell` или `wifi`), и профиль группы меняется вместе с ним.

## 5. Сценарий от провайдера

**Цель.** Провайдер передаёт профиль и использующий его сценарий в пакете, на который ссылается подписка.

```yaml
rcx: 1
profiles:
  fast-de:
    rcx: 1
    title: Fast Germany
    prefer:
      - label: Germany
        when: country = DE
      - label: Anything
        when: not dead
scenarios:
  work:
    rcx: 1
    title: Work
    description: Everything via Germany, internal sites direct.
    groups:
      $main: { profile: provider/fast-de }
    routes:
      - name: Intranet
        match: [DOMAIN-SUFFIX,corp.example]
        to: DIRECT
scenario: work
```

**Разбор по строкам.**

- `profiles.fast-de` — профиль провайдера, на который ссылаются как `provider/fast-de`.
- `scenarios.work` направляет основную группу через этот профиль, а корпоративные домены — напрямую.
- `scenario: work` делает этот сценарий используемым по умолчанию. Пользователь может выбрать другой сценарий или отключить автоматическое управление.
- Разместите пакет по URL `https` и объявите его в подписке: заголовок `reclash-routing: https://example.com/routing.yaml` или строка тела `#reclash-routing: https://example.com/routing.yaml`. Либо вставьте те же разделы в виде `rcx-profiles`, `rcx-scenarios` и `rcx-scenario` (см. [Обмен](sharing.md#доставка-провайдером)).
- Здесь нет обращений к сторонним узлам, поэтому запрос согласия не появляется.

**Что увидите.** После обновления подписки центр маршрутизации предложит сценарий провайдера «Work» с соответствующей меткой. При выборе маршруты применятся при следующем применении конфигурации.

## 6. Исключение тестовых серверов

**Цель.** Не использовать серверы с названиями, похожими на тестовые или пробные, даже в крайнем случае.

```yaml
rcx: 1
title: No test servers
pool:
  exclude: name ~ /(?i)test|demo|expired/ or tag(junk)
tags:
  junk: 'name ~ /(?i)^trial/'
prefer:
  - label: Anything
    when: not dead
```

**Разбор по строкам.**

- `pool.exclude` полностью удаляет сервер из пула: его нельзя выбрать ни на одном шаге.
- Условие объединяет регулярное выражение для имени и метку. `tag(junk)` проверяет метку, объявленную ниже.
- `tags.junk` совпадает с именами, начинающимися на «trial», без учёта регистра (`^` обозначает начало строки).
- Неизвестные факты разрешают сервер, но условия по имени никогда не бывают неизвестными.

Провайдер или сценарий могут таким же образом только сузить пул, но не расширить его.

**Что увидите.** Исключённые серверы остаются в рейтинге группы серыми, с причиной `Excluded by pool`.

## 7. Закрепление и ручное управление

**Цель.** Оставить выбранный сервер или полностью остановить работу движка.

Это настройка управления, а не YAML. Для группы доступны три режима.

| Действие | Режим | Результат |
| --- | --- | --- |
| Нажать сервер в умной группе | Закреплено | Движок оставляет этот сервер. Если он перестанет работать или выйдет из пула, группа вернётся к Auto и сообщит об этом. |
| При закреплении выбрать «Только эта сеть» | Закреплено, одна сеть | В других сетях закрепление сменится на Auto. |
| Выбрать для группы Manual | Вручную | Движок не переключает сервер и не тратит на группу проверки. |
| Выбрать Auto | Auto | Снимает закрепление и возвращает управление профилю. |
| Нажать «Сменить сервер» | Auto, текущий сервер исключён на 15 минут | Принудительно выполняет переключение. |

Закрепление также имеет приоритет над фиксированной целью сценария. Сценарий может удерживать группу на фиксированной цели с помощью программы:

```yaml
rcx: 1
title: Hold the main group on one server
groups:
  $main:
    to: DIRECT
```

**Что увидите.** Для закреплённой группы текущий сервер помечен как «выбран вами», а в объяснении показана причина `hold.pinned`. В журнале записываются события `pin` и `auto`.

> [!NOTE]
> **Снимок экрана `cookbook-pin-control`** — лист умной группы с режимами Auto, Pinned и Manual и выделенным закреплённым сервером.

## 8. Экспорт пакета сценария и его профилей

**Цель.** Передать другу сценарий вместе с нужным ему профилем.

На вашем устройстве сценарий называется `streaming` и использует профиль `streaming-fast`. Экспортируйте сценарий. Поскольку он ссылается на невстроенный профиль, результатом будет пакет:

```yaml
rcx: 1
kind: bundle
title: Streaming
scenarios:
  streaming:
    rcx: 1
    title: Streaming
    groups:
      $main: { profile: user/streaming-fast }
profiles:
  streaming-fast:
    rcx: 1
    title: Streaming fast
    extends: builtin/fastest
    prefer:
      - label: Germany
        when: country = DE
      - label: Anything
        when: not dead
```

**Разбор по строкам.**

- `kind: bundle` помечает файл; без этого ключа получатель прочёл бы его как один сценарий.
- `scenarios.streaming` ссылается на `user/streaming-fast` — экспортированное имя профиля.
- `profiles.streaming-fast` — сам профиль. `extends: builtin/fastest` остаётся ссылкой на встроенный профиль, доступный в каждой копии приложения.
- При экспорте профили получают имена из заголовков, а ссылки обновляются. Если у вас несколько профилей с названием «Streaming fast», имена будут `streaming-fast`, `streaming-fast-2` и далее.

При импорте друг получит сценарий и профиль с именами, свободными в его библиотеке. Если у него уже есть `streaming-fast`, существующий профиль не изменится: импортированный станет `streaming-fast-2`, а сценарий будет ссылаться на него.

`rcxlint` и студия проверяют этот файл именно в таком виде.

**Что увидите.** На экране проверки импорта до сохранения перечислены сценарий и профиль с итоговыми именами.

> [!NOTE]
> **Снимок экрана `cookbook-bundle-import`** — экран проверки импорта с одним сценарием и одним профилем, включая итоговые имена.
