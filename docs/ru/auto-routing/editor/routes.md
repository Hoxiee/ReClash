# Маршруты, порядок серверов и выбор значений

На этой странице описаны экраны из вкладки «Маршруты»: выбор трафика, редактор маршрута, редактор порядка серверов (лестницы), выбор страны и конструктор условий.

## Добавление маршрута для одного сервиса

1. Откройте **Автоматическую маршрутизацию** → вкладка **Маршруты**.
2. Нажмите **Добавить маршрут**. Страница называется **Новый маршрут**.
3. Выберите сервисы, которые обслуживает маршрут (см. [выбор трафика](#выбор-трафика)). Внизу написано: «Выберите сервисы для маршрута; при необходимости можно добавить собственные записи».
4. Нажмите **Далее**. Кнопка неактивна, пока ничего не выбрано.
5. Откроется [редактор маршрута](#редактор-маршрута); имя будет взято из первого выбранного сервиса. Если оно занято, поле останется пустым, и нужно будет ввести другое.
6. Выберите **Направлять через**, при необходимости измените порядок серверов и сохраните.

ReClash создаёт группу select с именем маршрута, добавляет маршрут в список и один раз повторно применяет профиль. Маршрут появляется в центре на вкладке «Маршруты» и в разделе «Прокси».

### Пользовательские записи

В разделе **Настраиваемые** («Домены, диапазоны IP, приложения или наборы правил для этого маршрута») нажмите **Добавить запись**. В форме есть:

| Элемент | Примечания |
| --- | --- |
| **Тип** | Меню типов записей (см. таблицу ниже). |
| **Значение** | Значение с подсказкой для выбранного типа. |
| **Не разрешать домены** | Показывается только для IP-типов. Не включайте без необходимости. |

| Тип | Совпадение | Пример |
| --- | --- | --- |
| **Домен и поддомены** | Домен и все его поддомены («Суффикс домена также охватывает все поддомены»). | `example.com` |
| **Домен** | Точное имя узла. | `www.example.com` |
| **Ключевое слово домена** | Любой узел с данным словом. | `example` |
| **Категория сайта** | Именованный список сайтов. | `category-ai-chat-!cn`, `telegram` |
| **Категория IP** | Страна или список IP-сервисов. | `telegram` |
| **Диапазон IP** | Блок CIDR; IPv6 определяется по двоеточию. | `10.0.0.0/8` |
| **Приложение** | Имя процесса (настольные системы). | `Telegram.exe` |
| **Набор правил** | Именованный набор правил профиля. | `my-rules` |

В строке указаны значение и тип. Нажмите строку для редактирования; удерживайте для **Удалить**.

### Проверка значений

| Сообщение | Причина |
| --- | --- |
| **Обязательное поле** | Значение пустое. |
| **Недопустимое значение** | Есть запятая или пробел в начале; домен содержит запрещённые символы; категория содержит символы вне `буквы, цифры, !@._-`; CIDR не является адресом с допустимым префиксом; порт или номер AS не числовой. |

Ограничения: до 128 записей на маршрут и до 32 маршрутов в сценарии.

## Редактор маршрута

> [!NOTE]
> **Снимок экрана `route-editor`** — редактор «▶️ YouTube»: имя, сводка трафика «YouTube · ещё 2», направление Auto, порядок серверов и поведение.

Заголовок — имя маршрута или **Новый маршрут**. Элементы сверху вниз:

| Элемент | Действие |
| --- | --- |
| **Имя** | Имя маршрута и создаваемой группы. Подсказка `▶️ YouTube`. |
| Сводка трафика | «YouTube · ещё 2»: сначала сервисы, затем пользовательские значения. Нажатие снова открывает выбор трафика. |
| **Направлять через** | Auto, Один сервер, Напрямую. |
| **Сервер** | Показывается для варианта «Один сервер». |
| **Порядок серверов** | Показывается для Auto. См. [ниже](#редактор-порядка-серверов). |
| **Поведение** | Показывается для Auto. |
| **Исключить** | Показывается для Auto (в программах есть также **Использовать**). Серверы исключаются из маршрута. |

### Правила имени

| Сообщение | Правило |
| --- | --- |
| **Обязательное поле** | Нужно указать имя. |
| **Имя слишком длинное** | Не более 64 байт в UTF-8 (каждый эмодзи занимает 4 байта). |
| **Это имя зарезервировано** | Запрещены `$main`, `*`, `GLOBAL`, `DIRECT`, `REJECT`. |
| **{label} уже существует** | У маршрута или группы подписки уже есть такое имя. |

Сохранение отключено, если имя некорректно, трафик не выбран или при варианте «Один сервер» не задан сервер.

### Направлять через

| Вариант | Значение |
| --- | --- |
| **Auto** | «Собственная группа маршрута выбирает лучший сервер из списка ниже». |
| **Один сервер** | «Этот трафик всегда проходит через выбранный сервер или группу». Выберите его в строке **Сервер**: список содержит разделы **Группы** и **Серверы**. Недоступен для правила «Все группы». |
| **Напрямую** | «Этот трафик обходит прокси». Только для обычных маршрутов. |

При переключении с Auto удаляются порядок серверов, поведение и исключения маршрута.

> [!NOTE]
> **Снимок экрана `route-editor-fixed`** — маршрут с вариантом «Один сервер», строка «Сервер» выбрана на «🇳🇴 Oslo 1».

Для правил группы (раздел «Другие группы») есть отдельный фиксированный вариант **Передать одному элементу** со строкой **Участник**. Описание: «Вся группа проходит через этот элемент без поиска серверов; выберите балансировщик или вложенную группу, чтобы передать ей весь трафик». Сводка: «Через {member}».

### Поведение

Нажмите **Поведение**, чтобы выбрать способ выбора серверов в заданном порядке.

> [!NOTE]
> **Снимок экрана `route-behaviour`** — страница поведения с разделами «Встроенные», «От провайдера», «Пользователь» и описанием внизу.

- Для маршрута по умолчанию используется встроенный Simple.
- Для правил группы первым пунктом будет **Собственный профиль группы** («Группа сохраняет поведение из собственных настроек»).
- Внизу показывается описание выбранного поведения.

### Использовать и исключить

Строки открывают [конструктор условий](#конструктор-условий). **Использовать** (по умолчанию «Любой сервер») сужает пул группы; **Исключить** (по умолчанию «Нет») удаляет серверы из пула. Например: исключить `Provider is …` или `Latency over …`.

> [!NOTE]
> **Снимок экрана `route-pool`** — в правиле группы строка «Исключить» показывает «имя содержит …», ниже строка «Использовать».

### Сохранение

При сохранении проверяется весь сценарий. Ошибки поля отображаются рядом с ним, остальные — в баннере. См. [устранение неполадок](troubleshooting.md).

## Редактор порядка серверов

Порядок серверов (в контракте — «лестница») задаёт приоритеты. Шаги образуют список: сначала проверяется шаг 1, затем 2 и так далее. Выигрывает первый шаг с работающим сервером. Неисправный сервер всегда занимает место после всех работающих, независимо от шага.

> [!NOTE]
> **Снимок экрана `route-editor-ladder`** — два шага («⚡ RU» и «Любой работающий сервер»), соединитель «если ни один не работает» и кнопка добавления шага.

### Список

Заголовок **Порядок серверов** и две кнопки: сортировка (если шагов не меньше двух) и **Добавить шаг**.

| Элемент | Значение |
| --- | --- |
| Номерной значок | Позиция шага; подсвечен, если в него попадает текущий сервер (только в листе группы). |
| Заголовок | Метка или краткое условие. |
| Подзаголовок | Условие и, если задано, отметка «Последний резерв». |
| Справа «N серверов» | Число подходящих серверов; красным при нуле. Только в листе группы. |
| Подпись между шагами | Первый соединитель: «если ни один не работает». |
| Пустой список | Строка **Любой работающий сервер** с подсказкой «Добавьте шаги, чтобы предпочесть одни серверы другим». |

Долгое нажатие на шаг открывает **Удалить**. Кнопка сортировки позволяет переставлять шаги. Если у маршрута нет собственных шагов, шаги его поведения показаны приглушённо с подсказкой «Из поведения — отредактируйте шаг, чтобы задать собственный порядок». При редактировании они сначала копируются в маршрут.

Если задано поведение при отсутствии подходящего шага, внизу показано: «Если нет шага с работающим сервером: {action}»; варианты **Перейти напрямую** или **Оставить текущий сервер**.

### Редактор шага

Нажмите **Добавить шаг** или существующий шаг. Заголовок — **Добавить шаг** или **Шаг {number}**; при редактировании отображается значок удаления.

> [!NOTE]
> **Снимок экрана `ladder-step-editor`** — редактор шага с «Имя содержит: ⚡ RU», строкой страны, кнопкой добавления условия и итогом «Сейчас подходят 2 сервера».

Раздел **Серверы на этом шаге**:

| Строка | Значение |
| --- | --- |
| **Имя содержит** | Текст в имени сервера, без учёта регистра. Символы `*` и `.` считаются буквальными. Сводка: «{text} в имени». |
| **Страна** | Открывает [выбор страны](#выбор-страны). Подзаголовок «Любая» или список стран (после двух стран отображаются только флаги). |
| **Все страны, кроме этих** | Переключатель, появляется после выбора стран. В сводке отображается «не {what}». |
| **Провайдер** | Серверы одного провайдера («от {provider}»). Варианты берутся из серверов. |
| **Протокол** | Тип сервера, например vless. |
| **Метка** | Именованный набор серверов; доступен, только если сценарий или профиль объявляет метки («метка {tag}»). |
| **Поддерживает UDP** | Только серверы с UDP («UDP»). |
| **Задержка меньше, мс** | По умолчанию 300 («меньше {ms} мс»). Только цифры. |
| **Другие условия** | Условие, которое нельзя представить быстрыми настройками; нажмите, чтобы редактировать текст. |
| **Добавить условие** | Меню дополнительных строк и пункта **Расширенное условие…**. |

У добавленных строк есть кнопка удаления. Все условия должны выполняться одновременно (связка «и»).

Внизу написано «Сейчас подходит {count} сервер» или «Сейчас подходят {count} сервера/серверов» по текущему набору серверов. Если условие нельзя проверить локально, строка скрыта.

Во втором разделе находятся **Метка** (подсказка — сводка условия) и **Последний резерв**. Подсказка: «Серверы в последнем резервном шаге используются, только если в остальных шагах нет работающего сервера, даже если шаг находится ниже».

### Пример: YouTube предпочитает ⚡ RU, затем любой сервер

1. Шаг 1: **Имя содержит** `⚡ RU`. Внизу: сейчас подходят 2 сервера.
2. Шаг 2: ничего не выбрано, отображается **Любой работающий сервер**.

Москва ⚡ 1 и 2 используются, пока работают; после отказа обоих подключение перейдёт на любой другой работающий сервер. Если поменять шаги местами, первый будет охватывать все серверы.

### Пример: Claude предпочитает Швецию

Один шаг с **Страна** = Швеция (🇸🇪 Stockholm 1 и 2). Добавьте вторым шагом **Любой работающий сервер**, если нужен резерв; без него при отказе всех серверов Швеции группе некого предпочесть.

### Последний резервный шаг

Добавьте шаг с включённым **Последний резерв** для серверов, используемых только при отказе остальных (например, Premium NL). Его можно поставить в любом месте списка: он всё равно будет применён последним.

## Выбор страны

> [!NOTE]
> **Снимок экрана `country-picker`** — окно выбора стран с разделом серверов пользователя: Норвегия (3 сервера, подтверждена), Швеция (2), Россия (2), и списком всех стран.

Открывается панель с поиском. Заголовок **Выберите страны** (несколько) или **Выберите страну** (одна; выбор закрывает панель).

| Раздел | Содержимое |
| --- | --- |
| **На ваших серверах** | Страны, найденные среди серверов, число серверов и метка «проверена», если страна выхода подтверждена проверкой. |
| **Все страны** | Все страны в алфавитном порядке. |

Поиск идёт по коду ISO, английскому или русскому названию. Выбранные строки отмечаются галочкой; в режиме множественного выбора нажмите галочку в панели, чтобы подтвердить.

Страна сервера определяется по подтверждённой стране выхода, если она известна; иначе — по имени в таком порядке: флаг emoji, отдельный заглавный двухбуквенный код ISO, английское название страны. Сервер без страны не соответствует условию страны и не вызывает проверку только ради определения страны.

## Конструктор условий

Используется для **Использовать**, **Исключить**, **Расширенное условие…**, дополнительных условий, меток и параметра **Распознавать, когда** для типов сети.

> [!NOTE]
> **Снимок экрана `condition-builder`** — конструктор с условием «Совпадают все»: страна — Норвегия или Швеция; задержка — меньше 300.

### Режим формы

| Элемент | Примечания |
| --- | --- |
| **Совпадение** | **Все условия** или **Любое условие**; показывается от двух условий. |
| **Условие {number}** | Раздел для каждой части, с кнопкой удаления. |
| **Поле** | См. таблицу ниже. |
| **Оператор** | **равно**, **не равно**, **одно из**, **соответствует**, **пройдена**, **не пройдена**, **меньше**, **не больше**, **больше**, **не меньше**, в том числе варианты с отрицанием. Для логических полей выбирается «да/нет». |
| **Значение** / **Значения через запятую** / **Шаблон** | Зависит от поля и оператора. |
| **Без учёта регистра** | Для оператора **соответствует** (регулярное выражение). |
| **Добавить условие** | Добавляет часть условия. |

| Поле | Значение |
| --- | --- |
| Имя | Имя сервера. |
| Страна | Проверенная страна выхода или страна из имени. |
| Провайдер, Протокол, Адрес сервера | Источник и характеристики сервера. |
| Поддерживает UDP | Сервер поддерживает UDP. |
| Работает, Не работает | Состояние сервера. |
| Измерен | Для сервера известна задержка. |
| Используется | Группа использует этот сервер. |
| Задержка, мс | Последняя задержка. |
| Страна выхода, Страна входа | Страна по результатам проверки. |
| Тип сети, Тип подключения, Страница входа, Тарифицируемая сеть | Условия сети. |
| Метка | Входит ли сервер в метку. |
| Проверка пройдена, Проверка не пройдена, Диагностика сети | Результаты проверок профиля. |

Для страны с оператором **одно из** значение выбирается в списке стран; с оператором **равно** выбирается одна страна.

Пустой конструктор показывает **Любой сервер** (для условий сети — **Всегда**).

### Текстовый режим

В разделе **Как текст** условие отображается строкой и редактируется на лету (проверяется примерно через 0,4 секунды после окончания ввода). Ошибка разбора показывает баннер и запрещает сохранение. Для условий со вложенными группами отображается: «Это условие содержит вложенные группы, поэтому редактируется как текст». Синтаксис описан в [conditions.md](../conditions.md).

> [!NOTE]
> **Снимок экрана `condition-text`** — раздел «Как текст» с баннером ошибки разбора.
