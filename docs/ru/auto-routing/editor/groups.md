# Лист группы

Лист группы в «Прокси»: состояние, управление, пул, поведение, объяснение, история и сообщения.

## Разделы

Лист открывается действием автомаршрутизации у группы-селектора в **Прокси** или из строки группы в центре.

| Раздел | Содержимое |
| --- | --- |
| Проблемы | Проблема группы; см. [Сообщения](#messages). |
| **Нужно разрешение** | «„{profile}“ хочет проверить эти сайты», узлы, **Разрешить**. До тех пор группа работает на `builtin/simple`. |
| Состояние | Сервер, причина, прогноз, страна выхода, уровень, тип сети, задержка. **Сменить сервер** ставит текущий сервер на 15 минут и переключает; недоступно в режиме «Вручную». |
| **Управление** | **Авто**, **Закреплён** или **Вручную**; см. [Управление](#control). |
| **Выбирать из** | Пулы в одно касание; см. [Выбирать из](#choose-from). Скрыт, когда группа держится на одном элементе. |
| **Поведение** | Профиль открывает выбор (**Встроенный**, **От провайдера**, **Мои**); также **Порядок серверов** и **Настройки группы**. Если группой управляет сценарий, внизу: «Сейчас этой группой управляет сценарий «{scenario}».» |
| **Почему этот сервер** | «Сравнено {count} серверов»; раскрывается до первых 8 строк ранжирования. |
| **История** | Последняя запись журнала; раскрывается до последних 20. |
| **Настройки автомаршрутизации** | Открывает центр. |
| **Создана маршрутом** или **Выключить автомаршрутизацию для этой группы** | Группа маршрута ведёт на **Изменить маршрут**. Иначе, для группы с собственной привязкой пользователя, убирает её; группа сохраняет свой сервер. |

Без привязки группа показывает **Если включить автомаршрутизацию** (профиль, который она получит, и число серверов) и **Включить автомаршрутизацию**: это добавляет привязку пользователя с профилем по умолчанию.

> [!NOTE]
> **Снимок экрана `group-sheet-auto`** — группа в режиме «Авто»: состояние, «Управление», «Выбирать из», «Поведение»

> [!NOTE]
> **Снимок экрана `group-intro`** — без автомаршрутизации, с кнопкой «Включить автомаршрутизацию»

> [!NOTE]
> **Снимок экрана `group-consent`** — «Нужно разрешение», узлы, «Разрешить»

> [!NOTE]
> **Снимок экрана `group-route`** — лист «▶️ YouTube», «Создана маршрутом»

## Управление

| Вариант | Управление движком |
| --- | --- |
| **Авто** | `auto`: решение принимается; закрепление снимается. |
| **Закреплён** | `pin` на текущий сервер во всех сетях: держится, пока работает, и возвращается к нему после восстановления. |
| **Вручную** | `manual`: пользователь выбирает в списке прокси; движок никогда не переключает и не проверяет. |

Ручной выбор сервера в группе «Авто» закрепляет его. См. [Управление](../engine.md#control).

> [!NOTE]
> **Снимок экрана `group-sheet-pinned`** — «Закреплён», «Держит закреплённый сервер»

## Выбирать из

Каждый чип задаёт `pool.include` привязки пользователя и возвращает закреплённую группу в «Авто».

| Чип | Пул |
| --- | --- |
| **Любой** | Без сужения. |
| Чипы провайдера и пользователя | `chips` привязки. |
| Флаги | До 8 флагов из имён серверов, самые частые первыми, если флагов хотя бы два. |
| **Добавить шаблон** | **Шаблон имени**, сохраняется как `name ~ /pattern/i`; не принимается, пока он неверен или ничего не находит («Подходят {count} из {total}»). |

Контекстное меню чипа пользователя удаляет его.

> [!NOTE]
> **Снимок экрана `group-change-to`** — «Любой», 🇳🇴, 🇸🇪, 🇷🇺 и один шаблон

## Поведение

| Строка | Что правит |
| --- | --- |
| Профиль | `profile` привязки. |
| **Порядок серверов** | `prefer` привязки, через [редактор шагов](routes.md#server-order). Пустой — следует профилю; порядок программы сценария важнее. |
| **Настройки группы** → **Серверы** | **Шаблон имени**: `pool.include`, как выше. |
| **Настройки группы** → **Поведение** | **Переключения**: `feel` — **Редко** (`calm`), **Сбалансированно**, **Часто** (`eager`). **Проверки**: `energy` — **Экономно**, **Сбалансированно**, **Точно**. |
| **Настройки группы** → **Сеть** | **Прямые сайты через эту группу** (если у профиля есть `direct-split`): **Включено сейчас** или **Ждёт: прямые сайты пока открываются**. |

> [!NOTE]
> **Снимок экрана `group-behaviour`** — Fastest, «Порядок серверов», «Настройки группы»

> [!NOTE]
> **Снимок экрана `group-settings`** — шаблон, «Переключения», «Проверки», «Прямые сайты»

## Объяснение

Каждая строка **Почему этот сервер** показывает сервер и задержку, затем причину исключения либо уровень и здоровье (**Работает**, **Работал раньше**, **Не проверялся**, **Не работает**), «может попасть в «{tier}» после проверки», «выход {country}», результаты проверок (✓ прохождение, × сбой, ~ мягкий сбой) и время последней проверки. **История** перечисляет переключения, сбои, закрепления и смены режима. Поля: [Объяснения и журнал](../engine.md#explanations-and-journal).

> [!NOTE]
> **Снимок экрана `group-why`** — «Почему этот сервер» со строкой «Пропущен после «Сменить сервер»»

> [!NOTE]
> **Снимок экрана `group-history`** — «История» с аварийным переключением и закреплением

## Сообщения

| Текст | Код |
| --- | --- |
| Управление вручную | `manual.requested` |
| Держит закреплённый сервер · Переключено на закреплённый {node} | `hold.pinned` · `switch.pinned` |
| Сценарий держит {node} · Сценарий переключает на {node} · {node} нет в этой группе | `hold.fixed` · `switch.fixed` · `fixed.missing` |
| Пауза, пока сеть — «{kind}»: ничего не проверяется и не переключается | `hold.paused` |
| Не используется: режим {mode} | `hold.idle` |
| Нет рабочих серверов; держит текущий · Нет рабочих серверов; запасной вариант — {node} | `stranded.no-candidates` · `switch.stranded` |
| Выбран лучший доступный сервер | `switch.initial` |
| Сервер сменён; {from} пропускается 15 минут | `switch.change-server` |
| {from} перестал работать; переключено на лучший запасной | `switch.failover` |
| {from} больше не входит в список | `switch.out-of-pool` |
| Нет другого рабочего сервера | `hold.no-alternative` |
| Это лучший сервер | `hold.best` |
| Проверяет лучшего кандидата | `hold.checking` |
| Работает; держится до сбоя | `hold.working` |
| Недавно переключался; выжидает перед следующим | `hold.dwell` |
| Достигнут лимит переключений ({limit} в час) | `hold.flap-limit` |
| Более быстрому серверу нужен ещё один замер | `hold.confirming` |
| Перешёл на сервер из «{tier}» · Ушёл с {from}: быстрее на {gain} мс | `switch.better-tier` · `switch.faster` |
| Не удалось выбрать сервер | `select.failed` |
| Похоже, пропала сеть; серверы не виноваты · Сеть сменилась | `network.suspect` · `network.changed` |
| Прямые сайты теперь идут через эту группу · Прямые сайты снова идут напрямую | `split.on` · `split.off` |
| Не входит в список · Исключён поведением · Не сервер · Пропущен после «Сменить сервер» · Не подходит ни под одно предпочтение · Ещё не проверен | `pool.no-match` · `pool.excluded` · `pool.unroutable` · `cooldown` · `no-tier` · `pending` |
| Поведение {profile} не найдено; используется стандартное | `profile.missing` |
| Ошибка поведения: {error} | `profile.invalid` |
| В текущей конфигурации эта группа не селектор · В группе нет серверов | `group.unavailable` · `group.empty` |
| Маршрут «{route}» пропущен: группа с таким именем уже есть. | `route.name-taken` |
| Маршрут «{route}» направляет трафик в «{to}», которого нет в профиле. | `route.to-missing` |
| Маршрут «{route}» не применён: {error} | `route.invalid` |
| Не удалось сохранить состояние маршрутизации: {error} | `store.failed` |

Строка прогноза называет конец удержания: «Перейдёт на {node}, как только проверка это подтвердит», «Может перейти на {node} через {minutes} мин» или «Перейдёт на {node}, если он останется быстрее на {gain} мс». Неизвестный код показывается как есть.
