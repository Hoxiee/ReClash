# Студия профилей групп

Профиль группы (или «поведение») задаёт, как умная группа выбирает сервер. В студии редактируется один профиль. Откройте её из центра: вкладка **Библиотека** → фильтр **Профили групп** → свой профиль (или любой другой, чтобы создать копию); либо выберите **Новый профиль** в меню с тремя точками. Центр находится в «Дополнительные настройки» → «Автоматическая маршрутизация».

Текстовый формат профилей описан в [profiles.md](../profiles.md).

> [!NOTE]
> **Снимок экрана `studio-form`** — форма студии с разделами «Общие», «Серверы», «Порядок серверов», «Метки» и «Поведение».

## Форма и текст

В меню справа вверху есть **YAML**. Он открывает полный текстовый редактор; сохранение заменяет содержимое формы. Форма отражает текст. Изменения формы заново формируют YAML из разобранного содержимого, поэтому комментарии, написанные вручную, не сохраняются. Имя и описание записываются после короткой паузы при вводе.

Кнопка с галочкой в верхней панели сохраняет профиль. Она отключена, пока в верхнем баннере есть ошибка или если изменений нет.

> [!NOTE]
> **Снимок экрана `studio-yaml`** — текстовый YAML-редактор профиля.

## Разделы формы

Новый профиль создаётся по шаблону: заголовок «Мой профиль», уровень Simple, один шаг «Working» (`not dead`), ранжирование по задержке и переключение «Редко».

Сверху вниз расположены: баннер, **Исходный профиль изменился** (если применимо), **Общие**, **Серверы**, **Порядок серверов**, **Метки**, **Поведение**, **Расширенные** (если используются), **Проверка** (если есть умная группа), **Предупреждения**, **Сайты, к которым будет выполнено подключение**.

| Раздел | Элемент | Примечания |
| --- | --- | --- |
| **Общие** | **Имя** | Заголовок профиля, подсказка «Новый профиль». |
| | Поле описания | Подсказка «Что делает этот профиль». |
| | **Уровень** | **Simple** или **Advanced**. |
| | **На основе** | Наследуемый профиль: **Нет** или любой другой профиль библиотеки. |
| **Серверы** | **Использовать** | Условие пула, по умолчанию «Любой сервер». |
| | **Исключить** | Условие исключения, по умолчанию «Нет». |
| **Порядок серверов** | Шаги | См. ниже. |
| **Метки** | **Добавить метку** | «Метка задаёт набор серверов для использования в шагах как tag(name)». |
| **Поведение** | **Переключение**, **Проверки**, **Если нет подходящего сервера** | Переключение и проверки работают как в настройках группы (**Редко**, **Сбалансированно**, **Часто**; **Экономно**, **Сбалансированно**, **Точно**). Для отсутствия сервера: **Оставить текущий** или **Перейти напрямую**. |
| **Расширенные** | только чтение | «Эти части редактируются в YAML». По строке для используемых частей: проверки доступности, типы сети, переопределения по сети, прямые сайты через группу, проверка страны выхода и переводы. Нажатие открывает YAML-редактор. |

### Порядок серверов

Студия использует такую же лестницу, как страница группы, с заголовком **Порядок серверов**. Шаги перечислены сверху вниз; выбирается первый шаг с работающим сервером. Между первыми шагами подпись «если ни один не работает». При пустом списке отображается строка «Любой работающий сервер» и подсказка «Добавьте шаги, чтобы предпочитать некоторые серверы другим».

- Кнопка «плюс» (**Добавить шаг**) добавляет шаг; нажмите шаг, чтобы открыть [редактор шагов](routes.md#редактор-шага), используемый маршрутами.
- Если шагов не меньше двух, кнопка сортировки включает перетаскивание. Долгое нажатие (или правый щелчок) открывает **Удалить**.
- В каждом шаге показаны метка или условие, отметка «Последний резерв» (если включена) и число подходящих серверов, если студия проверяет его для группы.
- Внизу повторяется параметр «Если нет работающего сервера в шагах: {action}» из **Если нет подходящего сервера**.
- Метка в шаге записывается как `tag(name)`. Имя содержит только латинские буквы, цифры, `-` и `_`, длина — до 24 символов; имя должно быть новым.

### Метки

Каждая метка — строка с условием. Нажмите для редактирования условия, удерживайте (или щёлкните правой кнопкой), чтобы удалить. **Добавить метку** запрашивает **Имя метки**, затем открывает конструктор условия.

## Условия в студии

Строки **Использовать**, **Исключить**, метки и расширенное условие шага открывают [конструктор условий](routes.md#конструктор-условий). Страны выбираются через [выбор страны](routes.md#выбор-страны).

## Предупреждения и проблемы

В верхнем баннере отображается первая ошибка и отключается сохранение. В **Предупреждениях** перечислены некритичные проблемы; если сообщение относится к строке текста, оно начинается с «Line {line}:». Когда предупреждений нет, раздел скрыт. Полный список см. в [troubleshooting.md](troubleshooting.md#проверки-профиля-и-сценария).

> [!NOTE]
> **Снимок экрана `studio-warnings`** — предупреждения: шаг повторяет более раннее условие, а метка не используется.

В разделе **Сайты, к которым будет выполнено подключение** перечислены узлы проверок профиля, для чего каждый используется (например, «проверка {name}»), а также пометка «сторонний», если нужно. Подпись: «Сторонние сайты не принадлежат ни вашему провайдеру, ни встроенным профилям».

## Проверка для группы

Раздел **Проверка** появляется, если существует хотя бы одна умная группа. В строке **Проверить для группы** можно выбрать **Нет** или умную группу. Выберите группу, чтобы увидеть, что сделал бы профиль сейчас, не применяя его. Под результатом перечислены до шести серверов рейтинга профиля с шагом, отметкой «может перейти в “{tier}” после проверки» или причиной исключения и задержкой; выбранный сервер подсвечен.

| Результат | Значение |
| --- | --- |
| **Оставить {pick}** | Группа уже использует сервер, который выбрал бы профиль. |
| **Выбрать {pick} вместо {now}** | Профиль переключил бы сервер. |
| **Серверов нет** | Ни один сервер не подходит. |

> [!NOTE]
> **Снимок экрана `studio-check`** — проверка для «Proxy»: «Выбрать 🇳🇴 Oslo 1 вместо 🇸🇪 Stockholm 1».

## Перенос изменений из оригинала

Если копия создана на основе встроенного профиля или профиля провайдера и оригинал изменился, появится раздел **Исходный профиль изменился**.

| Строка | Действие |
| --- | --- |
| **Перенести изменения** («Ваши правки останутся без изменений») | Объединяет новые изменения оригинала с вашей копией. |
| **Что изменилось** | Показывает построчное сравнение исходного профиля при копировании с новой версией. |

Сообщения: **Изменения перенесены**; «Перенесено; эти поля вы тоже изменили, поэтому ваши значения сохранены: {keys}»; либо **Не удалось перенести изменения**.

> [!NOTE]
> **Снимок экрана `studio-merge`** — раздел изменений оригинала с двумя строками.

## История и восстановление

В меню справа вверху есть **Предыдущие версии**. Пункт появляется, если у профиля есть старые версии. Выбор загружает версию в редактор; она сохраняется только после нажатия кнопки сохранения. При сохранении заменённый текст сохраняется; для каждого профиля хранится до 10 версий. В меню также есть **Экспорт**, а у сохранённого профиля — **Удалить** с подтверждением «Удалить “{profile}”?».

> [!NOTE]
> **Снимок экрана `studio-restore`** — список предыдущих версий с датой и временем.

## Студия сценариев

У редактора сценариев ([hub.md#the-scenario-editor](hub.md#редактор-сценария)) есть меню **YAML**, **Экспорт** и **Удалить** для сохранённого сценария, но нет **Предыдущих версий**. Форма соответствует вкладке «Маршруты».
