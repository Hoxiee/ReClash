# Заголовки запроса

Что ReClash отправляет при загрузке подписки, как выбирает клиентскую идентичность и как обрабатывает редиректы, статусы и резервные хосты.

## Заголовки клиента

| Заголовок | Значение |
| --- | --- |
| `User-Agent` | Задаётся [пресетом клиента](#client-presets). |
| `Accept-Encoding` | `gzip, deflate` |
| `Authorization` | `Basic` из userinfo в URL подписки. |
| `x-hwid` | Идентификатор устройства, только если [включён](#device-id). |
| `x-client`, `x-app-version`, `x-device-locale`, `Accept-Language` | Только с пресетами Happ и INCY. |

## Пресеты клиента

Настройка профиля «Запрашивать как» выбирает пресет. Новые профили используют «Автоматически», профили, созданные до появления настройки, — ReClash.

| Пресет | `User-Agent` | Дополнительные заголовки |
| --- | --- | --- |
| ReClash | `ReClash/v<version> clash-verge Platform/<os>` | — |
| FlClashX | `FlClash X/v0.4.2 core/v1.19.28 Platform/<os>` | — |
| Clash Meta | `ClashMetaForAndroid/2.11.36.Meta` | — |
| Clash | `ClashForAndroid/2.5.12` | — |
| Happ | `Happ/4.7.1/<Platform>/17912103176801703650` | `x-device-locale: <язык>` |
| INCY | `INCY/3.3.1` | `x-client: INCY`, `x-app-version: 3.3.1`, `x-device-locale: <локаль>`, `Accept-Language: <локаль>` |
| sing-box / Karing | `Karing/1.2.25.2802` | — |
| v2rayNG | `v2rayNG/2.3.11` | — |
| Свой User-Agent | Текст пользователя, не больше 512 символов, без управляющих символов | — |

`<os>` — `android`, `windows`, `macos` или `linux`. Общая настройка User-Agent приложения может заменить значение ReClash.

### Автоматический подбор

«Автоматически» сначала пробует последний успешный пресет, затем пресеты в порядке таблицы от ReClash до v2rayNG. Пресеты, которые отправили бы одинаковые заголовки, пропускаются. Выполняется не больше 8 попыток за 20 секунд.

Следующий пресет пробуется только при `406`, `415` или нераспознанном формате тела. Любая другая ошибка останавливает подбор. Метаданные `flclashx-*` действуют только с пресетом FlClashX ([«Имена FlClashX»](headers.md#flclashx-names)).

Пресет меняет только заголовки запроса и никогда не включает идентификатор устройства.

## Редиректы и транспорт

- Не больше 5 редиректов. Каждый ответ содержит ровно один `Location`. Циклы и редиректы с `https` на `http` завершаются ошибкой.
- При редиректе на другой origin остаются только `User-Agent`, `Accept` и `Accept-Language`. Идентификатор устройства и авторизация отбрасываются.
- `Content-Encoding` должен быть `gzip`, `deflate` или `identity` и встречаться один раз. Тела gzip и zlib распознаются также по сигнатуре.
- Тело может занимать 16 МиБ при передаче и 32 МиБ после распаковки. Пустое тело — ошибка.
- `Content-Type` не проверяется.

## Форматы ответа

ReClash определяет формат тела локально. Нативный Clash YAML сохраняется без преобразования; списки ссылок на узлы, Xray JSON (одна конфигурация или массив), sing-box JSON, WireGuard и поддерживаемые контейнеры Amnezia преобразуются в Clash YAML перед проверкой Core.

Списки ссылок принимаются как обычный текст, Base64 и Base64url. Поддерживаются в том числе схемы `mierus`, `socks5h`, `hysteria2+realm` и `hy2+realm`; ссылка Mieru может содержать несколько пар порт/протокол. Нераспознанные или некорректные ссылки на узлы внутри распознанного списка отмечаются как пропущенные.

Конвертация VLESS XHTTP сохраняет поддерживаемые параметры `extra`, включая заголовки, padding, повторное использование соединений и отдельное соединение загрузки. Неподдерживаемые или некорректные дополнительные параметры отмечаются как потери при конвертации. О неперенесённых разделах DNS, входящих подключений и других настроек также сообщается, в том числе для каждой конфигурации массива Xray. Потери требуют подтверждения либо ранее принятой политики импорта для этого источника; неподтверждённое обновление не меняет сохранённый профиль.

## Статус ответа

| Ответ | Результат |
| --- | --- |
| `x-hwid-max-devices-reached: 1` при любом статусе | Ошибка лимита устройств. Ошибка предлагает `reclash-supporturl` из того же ответа, если это ссылка `http(s)`. |
| `401`, `403` | Не авторизован. |
| `429` | Ограничение частоты. |
| `406`, `415` | Ошибка; «Автоматически» пробует следующий пресет. |
| Другой статус вне `2xx` | Ошибка. |
| `2xx` с пустым телом или без узлов, групп и удалённых провайдеров | Ошибка. |
| `2xx` в нераспознанном формате | Ошибка; «Автоматически» пробует следующий пресет. |

Неудачное обновление оставляет сохранённый профиль, его метаданные и политику без изменений.

## Резервные хосты

Оба поля работают только для подписок `https`. Путь и запрос URL подписки сохраняются, меняется только `host[:port]`.

| Заголовок | Значение | Поведение |
| --- | --- | --- |
| `reclash-fallbackhosts` | До 5 `host[:port]` | Пробуются по порядку после ошибки транспорта, TLS, тайм-аута, ограничения частоты или некорректного ответа основного хоста. Сохранённый URL не заменяют. |
| `reclash-newdomain` | Один `host[:port]` | Пробуется первым. После успешного обновления новый хост загружается и проверяется; профиль переходит на него, только если это удалось. Ошибка игнорируется. |

Резервные хосты берутся из сохранённых метаданных, поэтому их нужно доставить заранее, успешным обновлением. Запросы к ним несут те же заголовки, что и к основному хосту, включая идентификатор устройства.

```http
reclash-fallbackhosts: sub2.example.net, sub3.example.org:8443
reclash-newdomain: sub.example.com
```

## Идентификатор устройства

### Значения

| Заголовок | Значение |
| --- | --- |
| `x-hwid` | Первые 32 шестнадцатеричных символа в нижнем регистре от SHA-256 над `ReClash/HWID/v1\0` и идентификатором платформы. |
| `x-device-os`, `x-ver-os`, `x-device-model` | Название ОС, версия ОС и модель устройства. Все три заголовка отправляются вместе с `x-hwid`; значения, которые платформа не сообщает, остаются пустыми. |

Идентификатор платформы — `ANDROID_ID` на Android, `MachineGuid` на Windows, системный GUID на macOS и `/etc/machine-id` на Linux. Если его нет, используется случайное значение. Идентификатор хранится на устройстве, одинаков для всех профилей и не попадает в резервные копии. Это псевдонимный идентификатор, а не аппаратная аттестация.

### Согласие

- «Отправлять HWID» имеет общее значение и переопределение для профиля; «Как в настройках» следует общему значению.
- При включении показывается пояснение.
- Идентификатор отправляется только на origin URL подписки и на её резервные хосты. Редирект на другой origin его отбрасывает.
- Запросы [Preview API](preview-api.md) и логотипов его не несут.

## Статус устройства

| Заголовок | Значение | Действие |
| --- | --- | --- |
| `x-hwid-max-devices-reached` | `1`, `true` или `yes` | Обновление завершается ошибкой лимита устройств ([«Статус ответа»](#response-status)). |
| `x-hwid-not-supported` | `1`, `true` или `yes` | Показывается как «Статус устройства» в «Инспекторе подписки». |

Флаг учитывается, только если его заголовок отправлен один раз. Если заданы оба, побеждает лимит устройств.
