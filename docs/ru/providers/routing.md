# Доставка маршрутизации

Как подписка предлагает профили и сценарии автомаршрутизации: прямо в конфиге или в отдельном бандле маршрутизации.

Синтаксис профилей и сценариев описан в [«Профилях»](../auto-routing/profiles.md) и [«Сценариях»](../auto-routing/scenarios.md). Схема: [`rcx-profile.schema.json`](../../../rcx-profile.schema.json), бандл — в `$defs.bundle`.

## Каналы

| Канал | Когда использовать | Ключи |
| --- | --- | --- |
| В подписке | Провайдер отдаёт Clash YAML. | Верхнеуровневые `rcx-profiles`, `rcx-scenarios`, `rcx-scenario`; `rcx` у каждой группы `select`. |
| Бандл | Провайдер отдаёт формат, где этих ключей быть не может, или хочет версионировать маршрутизацию отдельно. | Заголовок `reclash-routing` или комментарий в теле со ссылкой на YAML-бандл. |

Обычный mihomo эти ключи игнорирует, поэтому подписка остаётся корректной для других клиентов Clash.

## Объявления в подписке

```yaml
rcx-profiles:
  fast-de:
    rcx: 1
    title: Fast Germany
    prefer:
      - { label: Germany, when: 'country = DE' }
      - { label: Anything, when: 'not dead' }
rcx-scenarios:
  work:
    rcx: 1
    title: Work
    groups:
      $main: { profile: provider/fast-de }
    routes:
      - name: Intranet
        match: [DOMAIN-SUFFIX,corp.example]
        to: DIRECT
rcx-scenario: work
proxy-groups:
  - name: Proxy
    type: select
    include-all: true
    rcx:
      profiles: [fast-de]
      default: fast-de
      chips:
        - { label: Germany, include: 'country = DE' }
```

| Ключ | Значение |
| --- | --- |
| `rcx-profiles` | Словарь «имя профиля → профиль». |
| `rcx-scenarios` | Словарь «имя сценария → сценарий». |
| `rcx-scenario` | Имя сценария по умолчанию. |
| `rcx` у группы | Привязка для этой группы `select`, см. ниже. |

### Привязка группы

| Ключ | Значение |
| --- | --- |
| `profiles` | Имена профилей, предложенных для группы. |
| `default` | Профиль, который действует, пока пользователь не выбрал свой. |
| `chips` | До 12 пулов в одно касание: `{label, include}`, где `include` — [условие](../auto-routing/conditions.md). |
| `pool` | Условия `{include, exclude}`, сужающие серверы группы. |
| `prefer` | Порядок серверов, заменяющий порядок профиля для этой группы. `prefer` программы сценария сильнее. |
| `feel` | Характер переключения: `calm`, `balanced` или `eager` ([«Как работает движок»](../auto-routing/engine.md)). |
| `energy` | Бюджет проверок: `eco`, `balanced` или `precise`. |

Профиль адресуется как `provider/<имя>`. `extends` может ссылаться на `builtin/<имя>` или на другой профиль провайдера.

## Бандл маршрутизации

```http
reclash-routing: https://example.net/rcx/bundle.yaml
```

```yaml
rcx: 1
profiles:
  fast-de:
    rcx: 1
    title: Fast Germany
    prefer:
      - { label: Germany, when: 'country = DE' }
groups:
  Proxy:
    profiles: [fast-de]
    default: fast-de
scenarios:
  work:
    rcx: 1
    title: Work
    groups:
      $main: { profile: provider/fast-de }
scenario: work
```

| Ключ | Значение |
| --- | --- |
| `rcx` | `1`. |
| `profiles` | Обязателен. Словарь «имя профиля → профиль». |
| `groups` | Словарь «имя группы прокси → привязка». |
| `scenarios` | Словарь «имя сценария → сценарий». |
| `scenario` | Имя сценария по умолчанию. |

- URL должен быть `https`; `http` допустим, только если сама подписка `http`. Без userinfo.
- Бандл загружается после подписки с теми же заголовками запроса. На другом origin уходят только `User-Agent`, `Accept` и `Accept-Language`; идентификатор устройства не передаётся.
- Не больше 256 КиБ и не пустой. Хранится рядом с профилем.
- Ошибка загрузки пишется в лог, обновление продолжается с сохранённым бандлом. Ответ без `reclash-routing` тоже оставляет сохранённый бандл.
- Бандл, который не является корректным YAML, игнорируется целиком.

## Приоритет

Объявления в подписке сильнее бандла по имени:

- `rcx` у группы заменяет привязку той же группы из бандла;
- запись `rcx-profiles` или `rcx-scenarios` заменяет запись бандла с тем же именем;
- непустой `rcx-scenario` заменяет `scenario`.

Выбор пользователя сильнее обоих.

## Ограничения провайдера

| Ограничение | Правило |
| --- | --- |
| Пул | Привязка провайдера может только сузить пул группы. |
| `direct-split` | От провайдера игнорируется; включить его может только пользователь. |
| Размер | Профиль или сценарий — не больше 64 КиБ. |
| Сторонние хосты | Профилю или сценарию, чьи проверки, диагностика или echo-сервисы обращаются к хосту вне сайта провайдера, нужно согласие пользователя. Сайт провайдера — регистрируемый домен хоста подписки; адреса встроенных профилей разрешены всегда. До согласия группа работает на `builtin/simple`. |
| Выбор | Профили и сценарии — это предложения: пользователь выбирает профиль для каждой группы и сценарий или выключает автоуправление. |

## Проверка

```sh
dart run tool/rcx.dart lint bundle.yaml
```

Линтер принимает профиль, сценарий или бандл. В приложении ядро показывает некорректный или отсутствующий профиль провайдера как проблему в статусе группы или сценария.
