# Политика безопасности

Что провайдер может закрепить в ReClash так, чтобы пользователь не мог это отменить.

Политика состоит максимум из двух частей. **Правило** лежит в теле подписки как обычный конфиг mihomo, поэтому его соблюдает любой клиент. **Переключатель** лежит в секции `policy` манифеста и заставляет ReClash это правило применять.

| Что нужно | Тело подписки | Манифест |
| --- | --- | --- |
| [Глобальный режим только через выбранные узлы](#only-listed-nodes-in-global) | Группа `GLOBAL` с этими узлами | `global: listed` |
| [Без глобального режима](#no-global) | Ничего | `global: off` |
| [Приложения Android всегда вне VPN](#apps-that-must-stay-outside-the-vpn) | `tun.exclude-package` | `apps: required` |
| [Без локальных портов прокси на Android](#no-local-proxy-ports) | Ничего | `local-ports: closed` |
| [Без редактирования панели](#locked-dashboard) | Ничего | `dashboard: locked` |

Каждый ключ необязателен. Если ключа нет, он ничего не ограничивает.

```yaml
policy:
  global: listed       # any (по умолчанию) | listed | off
  apps: required       # recommended (по умолчанию) | required
  local-ports: closed  # open (по умолчанию) | closed
  dashboard: locked    # editable (по умолчанию) | locked
```

## Только перечисленные узлы в глобальном режиме

Режим Rule остаётся свободным: решают ваши `rules`. В глобальном режиме трафик выходит только через узлы, достижимые из группы `GLOBAL`.

Проще всего нативный `filter` mihomo. Допустим, в парке есть узлы `Germany`, `Poland LTE`, `Russia LTE` и `Streaming`, а глобальный режим должен использовать только LTE.

Тело подписки:

```yaml
proxy-groups:
  - name: GLOBAL
    type: select
    include-all-proxies: true
    filter: '\bLTE\b'
    remnawave: { include-proxies: false }
```

Манифест:

```yaml
policy:
  global: listed
```

Результат:

| Режим и узел | Результат |
| --- | --- |
| Rule, любой узел, включая `Streaming` | Работает. |
| Global, `Poland LTE` | Работает. |
| Global, `Russia LTE` | Работает. |
| Global, `Germany` | Заблокировано. Приложение просит выбрать разрешённый узел или режим Rule. |
| Global, `DIRECT` | Заблокировано. Запрещённый маршрут никогда не уходит в прямое соединение. |

Что писать:

| Что нужно | Группа `GLOBAL` |
| --- | --- |
| Узлы с меткой в имени | `include-all-proxies: true` и `filter: '\bLTE\b'`. |
| Всё, кроме некоторых узлов | `include-all-proxies: true` и `exclude-filter: Streaming`. |
| Точный короткий список | `proxies` вручную. Хост, которого нет у пользователя, ломает конфиг, см. ниже. |

- `filter` сопоставляется только с именами узлов. Он сужает только члены `include-all-proxies` (или `include-all`), но не явные `proxies`.
- Обратная кавычка разделяет варианты. `(?i)` игнорирует регистр.
- Лучше `\bLTE\b`, чем `lte`: без якорей `lte` совпадёт и с `Malte`.
- `exclude-filter` и `exclude-type` убирают члены из любой группы, включая явные `proxies`.
- Метка должна быть в имени узла. `tags` хостов Remnawave в конфиг mihomo не попадают.
- Новые подходящие узлы подключаются сами, а пользователь, у чьего тарифа нет части подходящих хостов, всё равно получает загружаемый конфиг. Это удобно для больших парков.
- Если в `proxies` вручную указан хост, которого нет у пользователя, mihomo падает с ошибкой `GLOBAL: 'Poland LTE' not found`. Обновление профиля при этом проходит, а сбой проявляется только при применении конфига. При `global: listed` профиль блокируется и отказывает во всём трафике.

Что считается перечисленным:

| Случай | Результат |
| --- | --- |
| Узел из `proxies` тела, достижимый через `GLOBAL` | Разрешён. |
| Узел, в который `GLOBAL` разрешается через `filter` | Разрешён. |
| Узел переименован | Остаётся разрешён: разрешение привязано к серверу, порту и учётным данным, а не к имени. |
| Другой сервер взял имя разрешённого узла | Запрещён. |
| Узел из источника `proxy-providers` | Запрещён, если его определение не совпадает с разрешённым узлом из тела в точности. |
| `DIRECT` или `REJECT` в `GLOBAL` | Ничего не добавляют. |
| `filter` не совпал ни с одним узлом | Группа разрешается в `COMPATIBLE` (или в свой `empty-fallback`), глобальный режим убирается. |
| Группы `GLOBAL` нет, или из неё не достижим ни один узел тела | Глобальный режим убирается, как при `global: off`. |

> [!WARNING]
> Панель может добавлять узлы в ваши группы при генерации тела. Remnawave дописывает все хосты в `proxies` группы без `remnawave: { include-proxies: false }` ([как отказаться](rollout.md#policy-in-the-mihomo-template)), и это обходит `filter`. Тогда разрешено всё, а инспектор подписки показывает `policy.global is listed, but GLOBAL reaches every inline node of the body, so the lock restricts nothing`. Предупреждения нет, если в теле есть удалённые провайдеры или единственный маршрут. Проверяйте тело, которое реально получает клиент.

Только глобальный режим. В режиме Rule решают обычные группы и правила.

## Без глобального режима

```yaml
policy:
  global: off
```

Приложение скрывает глобальный режим, а ядро его отклоняет. Профиль в режиме Global переключается на Rule. В теле ничего не нужно.

## Приложения, которые должны оставаться вне VPN

Тело подписки:

```yaml
tun:
  exclude-package: [com.example.bank, com.example.gov]
```

Манифест:

```yaml
policy:
  apps: required
```

| Поведение | `recommended` (по умолчанию) | `required` |
| --- | --- | --- |
| Откуда список | `tun.exclude-package` и `apps.exclude` | Только `tun.exclude-package` |
| Пользователь может вернуть приложение | Да | Нет: заблокировано, метка «Обязательно у провайдера» |
| Режим белого списка или выключенный контроль доступа | Решает режим пользователя | Всё равно исключено |
| Локальные порты прокси на Android | Открыты | Закрыты |
| Десктоп | Игнорируется | Игнорируется |
| Android без режима VPN | Игнорируется | **Профиль отказывается подключаться** |

`apps: required` работает только на Android в режиме VPN; десктоп его игнорирует.

Исключённые приложения идут напрямую и видят настоящий IP. Исключение не блокирует их: для блокировки используйте режим lockdown в Android. Само VPN-приложение исключить нельзя.

Ошибки, которые может увидеть пользователь:

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| `provider policy requires Android VPN app exclusions` | Android без режима VPN | Использовать режим VPN на Android. |
| `provider app exclusions are not applied; restart the VPN` | Работающий VPN запущен с другим списком | Перезапустить VPN. |
| `provider policy could not identify this application` | Не удалось определить приложение соединения | Соединение остаётся заблокированным. |
| `provider policy requires this application to remain outside the VPN` | Приложение из списка всё ещё захвачено старой сессией VPN | Перезапустить VPN. |

## Без локальных портов прокси

```yaml
policy:
  local-ports: closed
```

Только Android. Закрывает порты mixed, HTTP, SOCKS, redir и TProxy, делает веб-панель недоступной и отправляет запросы самого приложения напрямую. `apps: required` включает это же поведение.

## Заблокированная панель

```yaml
policy:
  dashboard: locked
```

Убирает редактирование на обеих панелях. Раскладка из [`widgets`](manifest.md#widgets) остаётся.

## Когда действует блокировка

| Событие | Результат |
| --- | --- |
| Новый корректный манифест не содержит ключа | Эта блокировка снимается при следующем обновлении. |
| Значение в `policy` некорректно | Вся секция снимается, а [инспектор](rollout.md#subscription-inspector) показывает предупреждение. |
| Манифест не загрузился | Последняя корректная копия сохраняет блокировки. |
| Обновление подписки не удалось | Ничего не меняется. |
| В ответе больше нет `reclash-config`, или манифест ни разу не загружался | Блокировок нет. Правила тела работают как обычный конфиг mihomo. |
| Пользователь переключает профиль | Действует политика нового профиля. |
| Меняется режим или блокировка | Открытые соединения закрываются. |

Скрипты, переопределения и перезагрузка через контроллер не могут снять блокировку: ядро выводит её из исходного файла профиля и хранит вне `config.yaml`.

## Ограничения

- Это защищает клиент, который соблюдает правила, а не вашу сеть. Клиент, не читающий манифест, соблюдает только правила тела, а изменённый клиент может игнорировать и их. То, что не должно случиться никогда, запрещайте на сервере.
- Исключение пакета не распространяется на тот же сервис, открытый в браузере.
