# Заголовки ответа

Стандартные HTTP-заголовки, которые может нести ответ подписки, форматы их значений и единственный заголовок `reclash-config`, указывающий на манифест провайдера.

Все заголовки, синонимы и ограничения — в [«Реестре стандарта»](standard.md). Всё остальное, что провайдер сообщает ReClash, — в [«Манифесте провайдера»](manifest.md); заголовки устройства — в [«Заголовках запроса»](request.md#device-status).

## Разбор

- Имена заголовков не зависят от регистра.
- Поле читается из стандартного заголовка, затем из [синонимов других клиентов](#headers-from-other-clients). Побеждает первое корректное значение; манифест важнее обоих.
- Поле, отправленное больше одного раза, игнорируется: `Duplicate singleton`.
- Некорректное значение отбрасывается: `Invalid provider field`. Остальной ответ применяется.
- Значение заголовка больше 8 КиБ или всех заголовков больше 64 КиБ — загрузка завершается ошибкой.
- Поле, которого нет в ответе, отзывается; поля расхода остаются устаревшими ([«Время жизни метаданных»](README.md#metadata-lifetime)).
- Пустое значение `text` допустимо и заменяет сохранённое. Поля `url`, `integer` и `boolean` очистить нельзя.
- Метаданные читаются только из заголовков. Тело метаданных не несёт. Заголовок `reclash-*`, кроме `reclash-config`, `reclash-aliases` и `reclash-update`, игнорируется с предупреждением `Unsupported provider field` в «Инспекторе подписки».

## Форматы значений

| Тип | Синтаксис | Правила |
| --- | --- | --- |
| `text` | UTF-8, или `base64:` / `base64,` и Base64 от UTF-8 | Не больше 1024 байт после декодирования, если поле не указывает иное. Без управляющих символов; LF допустим в `announce`. |
| `url` | Абсолютный URL `http` или `https` | Нужен хост. Без userinfo, пробелов и управляющих символов. Не больше 1024 символов. |
| `integer` | Десятичное число | Умножается на масштаб синонима, затем проверяется диапазон. |
| `boolean` | `1`, `true`, `yes` / `0`, `false`, `no` | Без учёта регистра. |

## Subscription-Userinfo

```http
Subscription-Userinfo: upload=455727941; download=6174315083; total=107374182400; expire=1798761600
```

| Ключ | Значение |
| --- | --- |
| `upload`, `download` | Израсходованные байты. |
| `total` | Квота в байтах. `0` — без ограничения. |
| `expire` | Unix-время в секундах. `0` — бессрочно. |

Ключи не зависят от регистра и разделяются `;`. Значения — неотрицательные числа, дробная часть отбрасывается; `expire` не больше `8640000000000`. Повторённый ключ отбрасывается.

## Имя профиля

Профиль, которому пользователь не дал имя, получает первое доступное из:

1. имени файла из `Content-Disposition` (`filename*`, затем `filename`);
2. `profile-title` (text, 160 Б);
3. `provider.name` из [манифеста](manifest.md#provider);
4. хоста подписки.

Имя, заданное пользователем, никогда не заменяется. `profile-title` называет аккаунт, а не сервис.

## Интервал обновления

`profile-update-interval` задаёт интервал автообновления в часах. После пересчёта в минуты он должен быть в пределах 5–43200. Значение действует, только пока в редакторе профиля включён переключатель «Использовать интервал провайдера»; по умолчанию он включён. Ранее сохранённое положение переключателя не меняется. Поля манифеста для него нет.

## Синонимы

Четыре стандартных заголовка заполняют поле [`provider` манифеста](manifest.md#provider), если манифест его не задаёт. Если манифест задаёт поле, он важнее.

| Заголовок | Поле манифеста | Тип |
| --- | --- | --- |
| `support-url` | `provider.support-url` | url |
| `profile-web-page-url` | `provider.web-url` | url |
| `announce` | `provider.announce` | text, многострочный, 1024 Б |
| `hide-url` | `provider.hide-url` | boolean |

## Заголовки других клиентов

Заголовки, которые уже отправляют другие VPN-клиенты, читаются как синонимы существующих полей, поэтому провайдеру не нужно добавлять заголовки только для ReClash.

- Поле читается сначала из стандартного заголовка, затем из синонимов в порядке списка ниже. Побеждает первое корректное значение; некорректное отбрасывается с предупреждением, и берётся следующее.
- Размещённый манифест ([`reclash-config`](manifest.md)) важнее обоих.
- Если в ответе есть указатель на манифест, источник истины — манифест: синонимы отключены, пока ответ не пришлёт ещё и `reclash-aliases: 1`. Указатель, которым клиент не может воспользоваться (ответ не по `https`), не считается.
- Без указателя на манифест синонимы включены; `reclash-aliases: 0` отключает их. Значение, отличное от `1`, `true`, `yes`, `0`, `false` и `no`, отключает их в любом случае и даёт предупреждение `Invalid provider field`.
- Синонимы хостов (`transport.*`) читаются только из ответа по `https`.
- Синонимы несут только значения для отображения и транспорта. Настройки, приложения, маршрутизация и политика из них не читаются; заголовки вроде `flclashx-view`, `flclashx-widgets`, `flclashx-settings`, `flclashx-special`, маршрутизация Happ и заголовки отдельных приложений игнорируются.
- `profile-update-interval` пересчитывать не нужно: во всех проверенных клиентах он в часах, как в ReClash.
- Провайдер, перешедший на манифест, может и дальше отправлять эти заголовки для других клиентов.

| Заголовок-синоним | Клиент | Поле ReClash | Примечания |
| --- | --- | --- | --- |
| `flclashx-servicename` | FlClashX | `provider.name` | Текст; префикс `base64:` допустим. |
| `isp-name` | Karing | `provider.name` | Текст в percent-кодировании. |
| `flclashx-servicelogo` | FlClashX | `provider.logo` | Как у стандартного заголовка. |
| `profile-logo` | Koala Clash | `provider.logo` | Как у стандартного заголовка. |
| `homepage` | Incy | `provider.web-url` | Как у стандартного заголовка. |
| `isp-url` | Karing | `provider.web-url` | Как у стандартного заголовка. |
| `flclashx-buyplan` | FlClashX | `provider.renew.url` | `<url>[,<n>]`; `n` попадает в `provider.renew.days`. |
| `sub-expire-button-link` | Happ | `provider.renew.url` | Как у стандартного заголовка. |
| `flclashx-buytraffic` | FlClashX | `provider.top-up.url` | `<url>[,<n>]`; `n` попадает в `provider.top-up.percent`. |
| `announce-url` | Incy, v2RayTun | `provider.announce.url` | Как у стандартного заголовка. |
| `subscription-name` | Incy | имя профиля (пути в манифесте нет) | Задаёт имя профиля, как `profile-title`; текст, префикс `base64:` допустим. |
| `flclashx-newdomain` | FlClashX | `transport.fallback-hosts` | Список хостов, не более 5. |
| `new-domain` | Happ | `transport.new-domain` | Список хостов, не более 1. |

Форматы: значения `plain` следуют [форматам значений](#value-formats) стандартного заголовка; в `urlWithNumber` некорректное `n` отбрасывается с предупреждением, URL сохраняется; `hostList` принимает список через запятую из `host`, `host:port` или `scheme://host[:port]/...`, приведённый к `host[:port]`, без повторов и с ограничением длины.

## Указатель на манифест

```http
reclash-config: https://example.net/reclash.yaml
```

Заголовок `reclash-*`, который несёт манифест. Это `url`, и он учитывается, только если пришёл в ответе по `https`. Правила доставки — в [«Доставке манифеста»](manifest.md#delivery). Другие клиенты его игнорируют.

## Зеркало обновлений

```http
reclash-update: https://updates.example.net/update-manifest.json
```

`url`, который учитывается только по `https`. Он указывает на размещённую провайдером копию подписанного манифеста обновлений ReClash и читается из ответа подписки активного профиля.

- По умолчанию ReClash начинает с официального подписанного каталога и при сбое обращается к GitHub. Зеркало провайдера используется, если официальные источники недоступны.
- Флаг [`updates.prefer-mirror: true`](manifest.md#updates) в конфиге провайдера ставит его зеркало первым. Если оно корректно отвечает, что нового релиза нет, ReClash принимает этот ответ. При сбое зеркала приложение обращается к официальным источникам.
- Канал (стабильный или пре-релиз) и файл для своей платформы приложение выбирает из записей само. URL файлов должны быть `https`.
- Зеркало опрашивается дёшево: ReClash отправляет `If-None-Match` и `If-Modified-Since`, поэтому статический хост, отвечающий `304`, почти ничего не стоит. Отдавайте файл с `ETag` или `Last-Modified`.

### Формат манифеста

Каждый релиз ReClash публикует `update-manifest.json` как файл релиза:

```json
{
  "releases": [
    {
      "tag": "v1.2.3",
      "prerelease": false,
      "notes": "…",
      "assets": [{"name": "…", "size": 0, "sha256": "…", "url": "https://…"}],
      "signature": "…"
    }
  ]
}
```

Подпись Ed25519, сделанная ключом ReClash и проверяемая открытыми ключами, встроенными в приложение, охватывает тег, канал, заметки и поля `name`, `size` и `sha256` каждого файла. Зеркало может переписывать поля `url` и объединять записи нескольких манифестов, например последний стабильный релиз и последний пре-релиз, в один массив `releases`. Необязательное поле `published_at` задаёт дату для отображения. Приложение игнорирует записи с изменёнными подписанными полями.

```sh
# Направить все файлы на зеркало
jq --arg base https://cdn.example/reclash '.releases[].assets[] |= (.url = ($base + "/" + .name))' update-manifest.json

# Объединить два манифеста
jq -s '{releases: map(.releases[]) }' stable.json pre.json
```

Разработчики с репозиторием могут проверить файл: `dart run tool/update_manifest.dart verify <file> --key <public key>`.

### Время проверок

ReClash проверяет обновления при запуске и при возврате в приложение. После успешной проверки должно пройти хотя бы 15 минут со встроенным каталогом и час без него. После сбоя очередной возврат может запустить повтор через 2, 5, 15 или 30 минут, а подключение VPN может запустить его сразу. Сборка со встроенным каталогом обращается к резервному GitHub не чаще раза в час для каждого канала.

Когда один и тот же установщик доступен на GitHub и встроенном зеркале, ReClash замеряет загрузку небольшого фрагмента с каждого источника. Приложение начинает с самого быстрого источника, переключается при сбое и проверяет SHA-256 перед установкой.
