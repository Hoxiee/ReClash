# Отчёты и ссылки-исправления

Как пользователь одной кнопкой присылает всё о своей проблеме и как ответить ему ссылкой, которая её исправит.

## Отчёт

Пользователь нажимает «Сообщить о проблеме». Приложение проверяет подключение, опрашивает все серверы профиля и собирает результат в один архив. Пока пользователь сам его не отправит, ничего не покидает устройство.

Идентификатор отчёта (`RC-XXXX-XXXX`) есть в имени файла, в сводке и в каждом файле. Спрашивайте его первым.

```text
reclash-report-2026-11-04-1530-RC-7K3F-92QD.zip
├── README.md            что это и как читать
├── report.html          открыть в браузере: всё ниже на одной странице
├── 01-summary.md        вердикт, упавший шаг, находки, заметка пользователя
├── 02-findings.json     найденные проблемы и что пробовало автоисправление
├── 03-path.json         проверка подключения по шагам, с таймингами
├── 04-servers.csv       каждый сервер: DNS, TCP, задержка, ошибка
├── 05-services.json     сервисы через туннель и напрямую
├── 06-environment.json  файл hosts, чужие VPN и прокси, DNS, порты
├── 07-profile.json      ваши заголовки, время обновлений, группы, выбор
├── 08-history.json      последние 7 дней: инциденты, исправления, падения
├── 09-config.yaml       итоговый конфиг
├── logs/                core.log, app.log, logcat.txt, capture.log
└── report.json          приложение, ОС, устройство, язык, список файлов
```

В каждом JSON есть поле `schema` (`reclash.report.*@1`), так что панель может разбирать отчёты.

- **Что читать первым:** `report.html` или `01-summary.md`. `04-servers.csv` отличает «сервер лежит» от «сервер заблокирован в этой сети».
- **Маскировка:** пароли, UUID, ключи и токены в URL скрыты. При «публичной» маскировке хешируются ещё и хосты с IP. Отчёт, в котором остался бы секрет, не создаётся.
- **Размер:** до 10 МБ; первыми отбрасываются самые старые строки логов.

## Приём отчётов

По умолчанию пользователь отправляет архив в чат по ссылке `reclash-supporturl`. На телефоне — через системное меню «Поделиться», на компьютере приложение сохраняет файл, копирует сводку и открывает чат.

Чтобы получать отчёты напрямую, передайте адрес загрузки:

```http
reclash-support-upload: https://support.example.com/reclash/reports
```

Приложение один раз спрашивает пользователя, называя ваш домен, и отправляет:

```http
POST /reclash/reports HTTP/1.1
Content-Type: multipart/form-data; boundary=…

id=RC-7K3F-92QD
summary=<текст 01-summary.md>
report=<zip, application/zip>
```

Ответ `2xx` — успех. Необязательное JSON-тело: `{"ticket": "4211", "message": "Ответим в течение часа"}`; приложение покажет `message` (до 200 символов) и `ticket`. Принимаются только адреса `https`.

## Ссылки-исправления

Вы отвечаете ссылкой; пользователь нажимает её, видит, что она сделает, и подтверждает.

```text
reclash://fix?p=<payload>&s=<signature>
```

Посторонний такую ссылку не сделает: она подписана вашим ключом, и приложение сверяет её с ключом из вашей подписки.

### Ключ

Создайте ключ один раз и храните закрытую часть на своём сервере:

```sh
go run ./core/cmd/reclash-fix keygen -out key.txt
go run ./core/cmd/reclash-fix header -key key.txt
```

Отдавайте напечатанный заголовок вместе с подпиской:

```http
reclash-support-key: ed25519:O2onvM62pC1io6jQKm8Nc2UyFXcd4kOmOsBIoYtZ2ik
```

- Принимается только из подписки по `https`; обновляется при каждом обновлении подписки.
- До двух ключей через запятую, для ротации.

### Подпись ссылки

```sh
go run ./core/cmd/reclash-fix sign -key key.txt -report RC-7K3F-92QD -ttl 48h \
  profile.update proxy.select:group=Auto,node=NL-1
```

Флаги идут перед действиями. `-ttl` не больше `168h`. `verify -header 'ed25519:…' <ссылка>` проверяет ссылку.

### Действия

| Действие | Что делает |
| --- | --- |
| `profile.update` | Обновляет подписку |
| `profile.activate` | Делает ваш профиль активным |
| `proxy.select:group=G,node=N` | Выбирает узел в одной из ваших групп |
| `connections.reset` | Сбрасывает DNS и fake-IP, закрывает соединения |
| `core.restart` | Перезапускает ядро |
| `overrides.reset` | Сбрасывает переопределения пользователя (можно отменить) |
| `config.ruleMode`, `config.freePort`, `dns.ignoreSystemHosts`, `proxy.clearOwn`, `tunnel.freeDeviceName`, `tunnel.restart` | Исправления из каталога самого приложения |

Ссылка никогда не меняет адрес подписки, не добавляет профиль, не применяет конфиг и не открывает адреса. Она действует только на профиль, чей ключ её подписал.

### Когда ссылка отклоняется

Приложение ничего не применяет и объясняет причину, если:

- ссылка длиннее 2 КБ или повреждена;
- ключа нет ни в одной подписке пользователя;
- подпись не сходится;
- срок истёк или заканчивается больше чем через 7 дней;
- ссылку уже использовали;
- отчёт сделан не на этом устройстве, не для вашего профиля или старше 30 дней;
- в ней есть неизвестное действие.

Поэтому ссылка срабатывает один раз и только на том устройстве, где сделан отчёт.

### Формат

Для интеграции в панель без CLI. `p` — base64url от UTF-8 JSON, `s` — base64url подписи Ed25519 ровно над этими байтами, без выравнивания `=`.

```json
{"v":1,"kid":"E545QOZLVJE","rid":"RC-7K3F-92QD","exp":1767225600,"nonce":"AAECAwQFBgcICQoL","fix":[{"id":"profile.update"},{"id":"proxy.select","group":"Auto","node":"NL-1"}]}
```

- `kid`: base64url первых 8 байт SHA-256 от 32-байтного открытого ключа.
- `exp`: Unix-секунды. `nonce`: 12 случайных байт в base64url.
- Неизвестные поля отклоняются.

> [!TIP]
> Тестовый вектор: ключ из 32 нулевых байт даёт заголовок выше, а подпись этого JSON — `s=XEdYg90ecSzT7cV1dRxH9cCVLpw01KXGiWC1Lz4iUD0kYga2zSoZwr1VQnkXVkVlyx5D3L3fGx_ursuvQvmBDQ`.
