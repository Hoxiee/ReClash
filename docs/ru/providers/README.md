# Интеграция провайдера

Как провайдер подписки передаёт ReClash конфигурацию, метаданные, маршрутизацию и политику. Начните с [«Быстрого старта»](manifest.md#quick-start), затем откройте страницу нужной области.

## Модель

Подписка — это один HTTP GET. Тело — обычный mihomo; заголовки несут данные отдельного пользователя и один указатель на манифест, в котором лежит всё остальное.

| Канал | Что несёт | Справочник |
| --- | --- | --- |
| Тело | YAML конфига mihomo (Clash), только ключи, которые понимает mihomo. Ссылки, Xray, sing-box, WireGuard и Amnezia конвертируются при импорте и могут терять данные. Тела, зашифрованные AGE, сначала расшифровываются. Нативные группа `GLOBAL` и `tun.exclude-package` несут [политику безопасности](policy.md). | — |
| Стандартные заголовки | `Subscription-Userinfo`, `Content-Disposition`, `profile-title`, `profile-update-interval` и синонимы `support-url`, `profile-web-page-url`, `announce`, `hide-url`. | [«Заголовки ответа»](headers.md) |
| Заголовок `reclash-config` | Указатель на манифест и единственный заголовок `reclash-*`. Любой другой заголовок `reclash-*` игнорируется с предупреждением. | [«Указатель на манифест»](headers.md#manifest-pointer) |
| Манифест | Один статический YAML-файл, общий для всех пользователей: панель провайдера, напоминания, настройки, политика, приложения Android, транспорт, поддержка, оформление, карточки, подписи кнопки питания, маршрутизация. | [«Манифест провайдера»](manifest.md) |
| Заголовки устройства | `x-hwid`, `x-hwid-max-devices-reached` и связанные заголовки. | [«Заголовки запроса»](request.md) |
| Эндпоинт превью | JSON, который показывается до подтверждения импорта из браузера. Он работает до появления подписки, поэтому манифест использовать не может. | [«Preview API»](preview-api.md) |

## Цикл загрузки

1. Отправляет запрос с пресетом клиента профиля и, если включён, с идентификатором устройства ([«Заголовки запроса»](request.md)).
2. Проходит до 5 редиректов и декодирует тело ([«Редиректы и транспорт»](request.md#redirects-and-transport)).
3. Декодирует заголовки по [реестру](standard.md). Некорректные значения отбрасываются с предупреждением.
4. Сливает результат с сохранёнными метаданными ([«Время жизни метаданных»](#metadata-lifetime)).
5. Загружает манифест, на который указывает `reclash-config`, если он указан ([«Доставка»](manifest.md#delivery)).
6. Применяет конфигурацию, манифест и политику.

Обновление отклоняется, а сохранённый профиль не меняется, если тело пустое, его формат не распознан или в нём нет ни узлов, ни групп, ни удалённых провайдеров.

## Уровни доверия

| Уровень | Действие | Примеры |
| --- | --- | --- |
| `display` | Показывается пользователю. Поведение не меняет. | `provider.name`, `provider.announce`, `provider.hide-url` |
| `hint` | Меняет поведение в заданных рамках. | `settings`, `apps.exclude`, `reminders` |
| `consent` | Действует только с согласия пользователя. | `support.keys`, `support.upload-url` |

Большинство подсказок уступает изменениям пользователя ([«Владение»](manifest.md#ownership)). Только [`policy`](manifest.md#policy) задаёт ограничения, которые пользователь не может снять.

## Время жизни метаданных

Расход и манифест живут по-разному.

| Данные | Время жизни |
| --- | --- |
| Стандартные заголовки | Каждое успешное обновление накладывает их поверх сохранённых. Поле из ответа заменяет сохранённое значение. Отсутствующее поле расхода (`Subscription-Userinfo`) сохраняет последнее значение и помечается устаревшим; пока оно устарело, напоминания о сроке и трафике не приходят. Любой другой отсутствующий заголовок отзывается, а следовавшая за ним настройка возвращается к значению пользователя. |
| Манифест | Заменяется целиком после полной проверки. Неудачная или некорректная загрузка сохраняет последнюю корректную копию. Ответ без `reclash-config` удаляет сохранённую копию. Секция, которой нет в новой корректной копии, отзывается. |

Неудачное обновление ничего не меняет. [«Инспектор подписки»](rollout.md#subscription-inspector) показывает устаревшие поля и предупреждения.

## Версия стандарта

Реестр — стандарт версии 1. [«Реестр стандарта»](standard.md) генерируется из кода: заголовки, поля манифеста, типы, уровни доверия и ограничения размера. Машиночитаемая копия — [`provider_standard.g.json`](../../../provider_standard.g.json).

## Минимальный ответ

```http
HTTP/1.1 200 OK
Content-Type: text/yaml; charset=utf-8
Content-Disposition: attachment; filename*=UTF-8''Example%20VPN
Subscription-Userinfo: upload=0; download=2147483648; total=107374182400; expire=1798761600
profile-update-interval: 12
reclash-config: https://example.net/reclash.yaml

proxies:
  - name: Germany
    type: socks5
    server: de.example.net
    port: 1080
proxy-groups:
  - name: Proxy
    type: select
    proxies: [Germany]
rules:
  - MATCH,Proxy
```

```yaml
version: 1
provider:
  name: Example VPN
  support-url: https://t.me/example_support
```

## Совместимость

- Заголовки других клиентов читаются как стандартные: `Subscription-Userinfo`, `Content-Disposition`, `profile-title`, `profile-update-interval`, `profile-web-page-url`, `support-url`, `announce`, `hide-url`.
- Провайдеру, который уже отдаёт их, достаточно добавить один заголовок `reclash-config`. Другие клиенты его игнорируют. Панели Remnawave нужно одно правило ответа ([«Remnawave»](rollout.md#remnawave)).
- Пресет может представить ReClash другим клиентом ([«Пресеты клиента»](request.md#client-presets)). Он никогда не включает идентификатор устройства.
