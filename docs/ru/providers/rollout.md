# Доставка и отладка

Чек-лист запуска для провайдера, отдача заголовков и манифеста, проверка того, что получил ReClash, и разбор сбоев.

## Чек-лист запуска

### Подписка

- [ ] Тело — корректный конфиг mihomo хотя бы с одним узлом, группой или удалённым провайдером, без ключей `reclash-*` и `rcx-*`.
- [ ] `Subscription-Userinfo` есть и верен.
- [ ] Текст заголовков не в ASCII закодирован как `base64:`.
- [ ] Каждый заголовок отправляется один раз и проходит каждый слой прокси, включая CDN.
- [ ] `reclash-config` отправляется в ответе по `https` и указывает на URL `https`.
- [ ] `x-hwid-max-devices-reached` отправляется только при отказе устройству ([«Идентификатор устройства»](request.md#device-id)).

### Манифест

- [ ] Файл проходит `provider-config.schema.json` ([«Проверка в редакторе»](manifest.md#validate-in-your-editor)), а его маршрутизация — `dart run tool/rcx.dart lint`.
- [ ] Каждая секция, меняющая настройки, задана намеренно ([«Владение»](manifest.md#ownership)).
- [ ] Файл отдаётся по `https` по стабильному URL и весит не больше 512 КиБ.
- [ ] Резервные хосты отдают тот же путь и запрос.

### Политика

- [ ] Для `policy.global: listed` в теле есть группа `GLOBAL` с `filter` или `proxies`, которая даёт ровно те узлы, что вы разрешаете. Проверьте тело, которое получает клиент.
- [ ] Для `policy.apps: required` в теле есть `tun.exclude-package` ([«Политика безопасности»](policy.md)).
- [ ] Эндпоинт [Preview API](preview-api.md), если есть, не меняет состояние аккаунта.

### В приложении

- [ ] Обновите настоящий профиль, откройте [«Инспектор подписки»](#subscription-inspector): ни предупреждений, ни устаревших полей быть не должно.
- [ ] Дашборд показывает имя провайдера, карточки и настройки с меткой «От провайдера».
- [ ] Обновите профиль ещё раз: секции и настройки остаются применёнными.

## Отдача

- Отправляйте стандартные заголовки на сам URL подписки и один заголовок `reclash-config` с адресом манифеста. Прокси и CDN должны пропускать заголовки без изменений.
- Размещайте манифест на любом статическом HTTPS-хостинге ([«Доставка»](manifest.md#delivery)). Один общий URL — обычный случай; содержимое для отдельного пользователя требует URL с токеном.
- Заголовок `reclash-config` учитывается, только если пришёл в ответе по `https`, а редирект должен заканчиваться на `https`.
- Текст заголовков не в ASCII кодируйте как `base64:` ([«Форматы значений»](headers.md#value-formats)). Сырой UTF-8 в заголовках часто портится. Текст в манифесте — обычный UTF-8 YAML.
- Лимиты: 8 КиБ на значение заголовка, 64 КиБ на все заголовки, 512 КиБ на манифест. При превышении лимита заголовков загрузка завершается ошибкой.
- Отправляйте каждый заголовок один раз. Повторы игнорируются.
- Пропуск `reclash-config` удаляет сохранённый манифест. `x-hwid-max-devices-reached` проваливает обновление при любом статусе.
- Без возможности задавать свои заголовки ответа провайдер не получает возможностей ReClash сверх стандартных заголовков.

## Remnawave

Добавьте одно [правило ответа](https://docs.rw/docs/learn-en/routing-rules) в Subscription → Response Rules, выше стандартного правила `Fallback Base64`. Правила проверяются сверху вниз до первого совпадения.

```json
{
  "name": "ReClash",
  "description": "Mihomo config and manifest for ReClash",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    { "headerName": "user-agent", "operator": "STARTS_WITH", "value": "reclash", "caseSensitive": false }
  ],
  "responseType": "MIHOMO",
  "responseModifications": {
    "applyHeadersToEnd": true,
    "headers": [
      { "key": "reclash-config", "value": "https://example.net/reclash.yaml" }
    ]
  }
}
```

Правило делает две вещи:

- Отдаёт YAML для mihomo. `ReClash/…` не подходит ни под одно стандартное правило для клиентов, поэтому без этого правила панель по умолчанию отвечает через `Fallback Base64`. В списке Base64 нет ни группы `GLOBAL`, ни `tun.exclude-package`, поэтому `policy` нечего применять.
- Отправляет манифест только ReClash. Другие клиенты заголовка не видят.

Другие варианты отдачи манифеста:

| Кто получает манифест | Куда поставить заголовок |
| --- | --- |
| Только ReClash | Правило выше. |
| ReClash, свой манифест на тариф | Удалите `headers` из правила и добавьте заголовок каждому внешнему скваду (Users → External Squads → сквад → Headers). Пользователи вне сквада манифест не получат. Другие клиенты этого сквада тоже получат заголовок и проигнорируют его. |
| Все клиенты | Subscription → Settings → Response headers. Другие клиенты его игнорируют. |

Заголовок, оставленный в правиле с `applyHeadersToEnd: true`, перекрывает заголовок сквада.

### Политика в шаблоне mihomo

`GLOBAL` и `tun.exclude-package` положите в шаблон mihomo, а включите секцией `policy` ([«Политика безопасности»](policy.md)). Чтобы другие клиенты их не получали, дайте ReClash отдельный шаблон через `subscriptionTemplate` в `responseModifications` правила.

> [!WARNING]
> Remnawave добавляет все хосты в каждую группу без `remnawave: { include-proxies: false }`, даже если у группы есть `filter`. Без этой настройки `global: listed` разрешает все хосты, а [инспектор](#subscription-inspector) предупреждает: `policy.global is listed, but GLOBAL reaches every inline node of the body, so the lock restricts nothing`. Задайте её для `GLOBAL` и для всех групп, достижимых из `GLOBAL`. Имя хоста должно содержать метку фильтра, потому что `tags` хостов в конфиг не попадают.

```text
proxy-groups:
  - name: GLOBAL
    type: select
    include-all-proxies: true
    filter: '\bLTE\b'
    remnawave: { include-proxies: false }
```

### Что важно знать

- Давайте пользователям базовый URL подписки. URL конкретного типа, например `/<short>/mihomo`, обходит правила ответа, поэтому манифеста в нём нет.
- Правило зависит от User-Agent, а его может сменить пользователь. Кто выберет другой [пресет клиента](request.md#client-presets), останется без манифеста и без блокировок. Если это важно, отправляйте заголовок всем клиентам, а правило оставьте только для YAML.
- `Subscription-Userinfo` и `Content-Disposition` приходят с каждым ответом-конфигом. `profile-title`, `profile-update-interval`, `support-url` и `profile-web-page-url` берутся из Response headers, которые новая панель заполняет по умолчанию. Для `announce` нужна настройка HWID `maxDevicesAnnounce`. ReClash читает их все как стандартные заголовки.
- Разместите манифест на любом статическом хостинге ([«Быстрый старт»](manifest.md#quick-start)).

Проверено на Remnawave 3.4.7. В других версиях названия в панели могут отличаться.

## Проверка

Повторите запрос с пресетом ReClash:

```sh
curl -sS -D - -o /dev/null \
  -H 'User-Agent: ReClash/v1.0.0 clash-verge Platform/android' \
  -H 'Accept-Encoding: gzip, deflate' \
  'https://sub.example.net/s/TOKEN'
```

Загрузите манифест, на который указывает заголовок, и убедитесь, что это обычный YAML по `https`:

```sh
curl -sS -D - 'https://example.net/reclash.yaml'
```

В приложении:

| Где | Что показывает |
| --- | --- |
| Редактор профиля → «Совместимость» → «Проверить» | Пресет, который сработал, распознанный формат и число узлов. Ничего не сохраняет. |
| «Профили» → меню профиля → «Инспектор подписки» | Что декодировано и сохранено ([«Инспектор подписки»](#subscription-inspector)). |
| Дашборд и настройки приложения | Применённые подсказки с меткой «От провайдера». |

## Инспектор подписки

| Пункт | Значение |
| --- | --- |
| «Источник» | `http`, если хотя бы одно поле пришло из заголовков, иначе `body`. |
| «Получено» | Время последнего успешного обновления. |
| «Статус устройства» | `limitReached` или `unsupported`, если сервер их прислал. |
| «Предупреждения» | Предупреждения декодера и манифеста, например привязка к отсутствующей группе, `Invalid provider field`, `Duplicate singleton`, `Unsupported provider field`. |
| «Поля» | Сохранённые поля по имени заголовка, с уровнем доверия и меткой `stale`, если поле расхода отсутствовало в последнем ответе. |

## Частые сбои

| Симптом | Причина |
| --- | --- |
| Поля заголовка нет, есть `Invalid provider field` | Значение нарушает свой тип: URL с userinfo, управляющие символы, число вне диапазона. |
| Манифест не применяется | `reclash-config` пришёл не в ответе по `https`, URL или редирект не `https`, файл больше 512 КиБ, некорректный YAML или `version` не `1`. Последняя корректная копия остаётся; предупреждения — в инспекторе. |
| Секция манифеста ничего не делает | Секция некорректна и проигнорирована с предупреждением, либо неизвестный ключ проигнорирован. Посмотрите инспектор. |
| Прежние значения из манифеста пропали | В новой корректной копии нет секции или в ответе нет `reclash-config`. Оба случая отзывают значения. |
| `Unsupported provider field` для заголовка `reclash-*` | Читается только `reclash-config`. Перенесите значение в манифест. |
| Напоминания перестали приходить | Поле расхода устарело, нет `Subscription-Userinfo`, `expire=0` или `total=0`. |
| Интервал обновления не действует | В редакторе профиля выключено «Использовать интервал провайдера»; по умолчанию оно выключено. |
| Интервал отклонён | Меньше 5 или больше 43200 минут после пересчёта из часов. |
| Настройка больше не следует провайдеру | Её изменил пользователь. «Вернуть провайдеру» возвращает её. |
| Резервные хосты не пробуются | Подписка `http`, хостов ещё нет в сохранённом манифесте или ошибка — `401`, `403` либо лимит устройств. |
| Секция `transport` проигнорирована | `new-domain` задан списком или `fallback-hosts` задан строкой. |
| Привязка маршрутизации не применяется | Привязка называет группу, которой нет в теле, например после переименования. Обновите манифест. |
| Пропал режим Global | `policy.global: off` или `policy.global: listed` при группе `GLOBAL`, которая не разрешается ни в один узел. |
| «Перезапустите VPN» с политикой | Обязательные исключения изменились, пока VPN работал. |
| Автоматический подбор останавливается на первой ошибке | Следующий пресет пробуется только при `406`, `415` и нераспознанном формате тела. |
| Текст не в ASCII искажён | UTF-8 прямо в заголовке. Используйте `base64:`. |
