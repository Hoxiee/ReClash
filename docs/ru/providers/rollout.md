# Доставка и отладка

Отдача заголовков, проверка того, что получил ReClash, разбор частых сбоев и выкатка изменений.

## Отдача заголовков

- Отправляйте метаданные заголовками ответа на сам URL подписки. Прокси и CDN должны пропускать заголовки `reclash-*` без изменений.
- Текст не в ASCII кодируйте как `base64:` ([«Форматы значений»](headers.md#value-formats)). Сырой UTF-8 в заголовках часто портится.
- Лимиты: 8 КиБ на значение и 64 КиБ на все заголовки. При превышении любого загрузка завершается ошибкой.
- Отправляйте каждый заголовок один раз. Повторы игнорируются.
- Если заголовки задать нельзя, используйте [комментарии в теле](headers.md#body-comments) в начале конфига.
- Чтобы убрать сообщение, отправьте пустое значение. Пропущенный заголовок отзывает сообщение.
- Отправляйте `x-hwid-max-devices-reached` только при отказе устройству: он проваливает обновление при любом статусе.

## Проверка

Повторите запрос с пресетом ReClash:

```sh
curl -sS -D - -o /dev/null \
  -H 'User-Agent: ReClash/v1.0.0 clash-verge Platform/android' \
  -H 'Accept-Encoding: gzip, deflate' \
  'https://sub.example.net/s/TOKEN'
```

В приложении:

| Где | Что показывает |
| --- | --- |
| Редактор профиля → «Совместимость» → «Проверить» | Пресет, который сработал, распознанный формат и число узлов. Ничего не сохраняет. |
| «Профили» → меню профиля → «Инспектор подписки» | Что декодировано и сохранено ([«Инспектор подписки»](#subscription-inspector)). |
| Дашборд и настройки приложения | Применённые подсказки с меткой «От провайдера». |

Маршрутизацию проверяйте через `dart run tool/rcx.dart lint`, политику — по [`provider-policy.schema.json`](../../../provider-policy.schema.json).

## Инспектор подписки

| Пункт | Значение |
| --- | --- |
| «Источник» | `http`, если хотя бы одно поле пришло из заголовков, иначе `body`. |
| «Получено» | Время последнего успешного обновления. |
| «Статус устройства» | `limitReached` или `unsupported`, если сервер их прислал. |
| «Предупреждения» | Предупреждения декодера, например `Invalid provider field`, `Duplicate singleton`, `Unsupported provider field`. |
| «Поля» | Сохранённые поля по имени заголовка, с уровнем доверия и меткой `stale`, если поле расхода отсутствовало в последнем ответе. |

## Частые сбои

| Симптом | Причина |
| --- | --- |
| Поля нет, есть `Invalid provider field` | Значение нарушает свой тип: плохой токен, число вне диапазона, URL с userinfo, управляющие символы. Один плохой токен или хост делает некорректным всё поле. |
| `Unsupported provider field` | Опечатка в имени заголовка или `flclashx-*` не с пресетом FlClashX. |
| После удаления заголовка значение пропало | Пропущенный заголовок отзывает значение. Поля расхода остаются устаревшими. |
| Напоминания перестали приходить | Поле расхода устарело, нет `Subscription-Userinfo`, `expire=0` или `total=0`. |
| Интервал обновления не действует | В редакторе профиля выключено «Использовать интервал провайдера»; по умолчанию оно выключено. |
| Интервал отклонён | Меньше 5 или больше 43200 минут после масштабирования. |
| Настройка больше не следует провайдеру | Её изменил пользователь. «Вернуть провайдеру» возвращает её. |
| Резервные хосты не пробуются | Подписка `http`, хосты пришли в том же неудачном ответе или ошибка — `401`, `403` либо лимит устройств. |
| Бандл маршрутизации не применяется | Не `https` при подписке `https`, больше 256 КиБ, пустой или некорректный YAML. Ошибки загрузки попадают в лог приложения. |
| Пропал режим Global | `noglobal` или политика с `global.allow: []`. |
| Импорт с политикой не проходит | Неизвестный ключ или версия; повторяющийся или неизвестный `reclash-id`. |
| «Перезапустите VPN» с политикой | Обязательные исключения изменились, пока VPN работал. |
| Автоматический подбор останавливается на первой ошибке | Следующий пресет пробуется только при `406`, `415` и нераспознанном формате тела. |
| Текст не в ASCII искажён | UTF-8 прямо в заголовке. Используйте `base64:`. |

## Чек-лист выкатки

- [ ] Тело — корректный конфиг mihomo хотя бы с одним узлом, группой или удалённым провайдером.
- [ ] `Subscription-Userinfo` есть и верен.
- [ ] Текст не в ASCII закодирован как `base64:`.
- [ ] Каждый заголовок отправляется один раз и проходит каждый слой прокси.
- [ ] «Инспектор подписки» не показывает предупреждений и устаревших полей.
- [ ] Подсказки, меняющие настройки, заданы намеренно: [«Настройки приложения»](app-settings.md).
- [ ] Бандл маршрутизации и профили в подписке проходят `rcx.dart lint`.
- [ ] Политика, если есть, проходит схему, а каждый `reclash-id` уникален.
- [ ] Резервные хосты отдают тот же путь и запрос.
- [ ] Работа с идентификатором устройства соответствует [«Идентификатору устройства»](request.md#device-id); `x-hwid-max-devices-reached` отправляется только при отказе.
- [ ] Эндпоинт [Preview API](preview-api.md), если есть, не меняет состояние аккаунта.
