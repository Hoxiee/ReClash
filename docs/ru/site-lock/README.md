# Привязка сайтов

Привязка сайтов закрепляет выбранные сайты за выбранными выходными серверами: их трафик уходит только через один из этих серверов или не уходит вовсе, какими бы ни были режим, правила и выбранный прокси. Остальной трафик идёт как обычно.

## Как работает привязка

Ядро сверяет каждое новое соединение с включёнными привязками раньше режима и правил. Соединение, попавшее под привязку, уходит через первый из её серверов, прошедший последнюю проверку задержки, а если не прошёл ни один — через первый. Если в запущенном профиле нет ни одного сервера привязки, соединение отклоняется. Привязанный сайт никогда не идёт напрямую, даже в режиме «Напрямую».

Выходной сервер запоминается по типу, адресу и порту, а не по имени, поэтому переименование сервера и обновление подписки привязку не ломают. Группы прокси и встроенные DIRECT и REJECT выходами быть не могут.

## Создание привязки

Откройте **Инструменты → Расширенная конфигурация → Привязка сайтов** и нажмите **+**.

- **Имя** необязательно; без него в списке показывается первый сайт.
- **Сайты** — по одной записи на строку.
- **Исключения** — записи, которые остаются вне привязки, даже если подходят под **Сайты**.
- **Выходные серверы** — серверы запущенного профиля. Сервер, на который указывают несколько имён, занимает одну строку. Список загружается только при работающем ядре; сохранённые серверы остаются в привязке в любом случае.

| Что ввести | Как сохранится |
| --- | --- |
| `chatgpt.com`, `*.chatgpt.com` или `.chatgpt.com` | `DOMAIN-SUFFIX,chatgpt.com` |
| `geosite:openai` | `GEOSITE,openai` |
| `1.2.3.4` | `IP-CIDR,1.2.3.4/32` |
| `2001:db8::/32` | `IP-CIDR6,2001:db8::/32` |
| Правило mihomo без цели, например `DOMAIN,api.openai.com` или `DOMAIN-KEYWORD,openai` | Как введено |

В привязке до 128 записей и до 16 выходных серверов, всего привязок — до 32. Ядро проверяет весь список при сохранении: если оно отклоняет хотя бы одну запись, действуют прежние привязки, а страница показывает причину.

## Статусы

| Статус | Что значит |
| --- | --- |
| Через *сервер* | Привязанные соединения уходят через этот сервер. |
| Все выходы недоступны | Все выходы провалили последнюю проверку задержки; соединения всё равно пробуют первый. |
| В профиле нет выходного сервера | В запущенном профиле нет ни одного сервера привязки, поэтому привязанные соединения отклоняются. |
| Выключено | Привязка выключена. |
| Ожидание ядра | Ядро ещё не сообщило статус этой привязки. |

## Вне туннеля на Linux

На Linux при включённом TUN и установленном Helper привязка держится ещё и в системном файрволе. Вне интерфейса TUN Helper отклоняет трафик к привязанным адресам и к диапазону fake-ip и отбрасывает DNS-запросы привязанных имён. Это работает, пока ядро остановлено или упало, а при загрузке системы Helper восстанавливает привязку ещё до запуска ReClash. Чтобы открыть привязанный сайт напрямую, выключите его привязку.

> [!IMPORTANT]
> Пока включена хоть одна привязка, каждый DNS-запрос вне туннеля проходит через Helper. Если Helper остановится, эти запросы тоже остановятся, а не утекут.

На отброшенный DNS-запрос никто не отвечает, поэтому приложение ждёт собственного таймаута, прежде чем сдаться на привязанном имени.

## Ограничения

- **Windows, macOS и Android** получают только слой ядра: когда ядро остановлено, привязанные сайты ничто не блокирует.
- **TUN выключен**: привязка действует только на трафик, который идёт через ядро, а системный файрвол ничего не блокирует.
- **Сниффинг выключен**: соединение, имя которого ядро не разрешало само, приходит голым адресом и не совпадает с доменными записями. Страница предупреждает, когда это так.
- **Записи только для ядра**: записи, которые системный файрвол повторить не может, — отрицание атрибутов geosite, регулярные выражения с lookaround, логические и портовые правила — держатся только пока работает ядро. Страница перечисляет привязки с такими записями.
- **Зашифрованный DNS в браузерах**: DNS over HTTPS и DNS over TLS идут мимо DNS-фильтра Helper. Пока ядро работает, это не важно, но после его падения такой браузер может разрешить и открыть привязанный сайт. Выключите безопасный DNS в браузере: в Chrome — **Настройки → Конфиденциальность и безопасность → Безопасность → Использовать безопасный DNS**, в Firefox — **Настройки → Приватность и защита → DNS через HTTPS**.
- **Зашитые адреса**: приложение, которое подключается по заранее известному адресу, ловится только адресными записями. Для таких сервисов добавьте записи `IP-CIDR`.
