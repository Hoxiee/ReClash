# 自动路由页面

自动路由页面是自动路由的主页面。打开**工具** → **自动路由**。页面是单个屏幕，没有选项卡，自上而下依次为：授权卡片、总开关和运行中的场景、模式、运行中场景的**路由**和**更多**、**分组**，以及最后的**库**行。

## 首次显示前

| 显示内容 | 原因 | 操作 |
| --- | --- | --- |
| **没有订阅**，并提示“请先添加订阅；自动路由使用订阅中的组”。 | 尚未选择配置。 | 添加订阅。 |
| **启动连接以查看自动路由** | Core 未运行，没有实时数据。 | 启动连接。 |

## 开启自动路由

1. 打开**工具** → **自动路由**。
2. 开启**自动路由**。

应用会启动上次选择的场景。如果从未选择过场景，则启动内置场景**所有组**，使订阅中的每个 select 组都成为智能组。关闭开关时，页脚显示：“开启后，场景会为你的组和路由选择服务器”。如果场景存在问题（例如需要授权），开关下方会显示问题文本而不是普通说明。没有运行场景时，页面只显示开关、**分组**和**库**行。

### 选择场景

场景行显示当前运行场景的标题和说明。点按**更换**，打开快速切换面板。

| 分区 | 内容 |
| --- | --- |
| **我的** | 你创建或另存为副本的场景。 |
| **来自服务商** | 订阅提供的场景。 |
| **内置** | 随 ReClash 提供的场景，例如“所有组”。 |

点按场景即可运行。选择场景不会修改它；编辑方式见[编辑副本](#编辑副本)。

### 实时状态行

场景行下方显示**网络：<kind> · 模式：<mode>**。副标题说明当前模式由谁决定：

| 副标题 | 含义 |
| --- | --- |
| 场景在此网络下设置模式 | 模式由场景选择。 |
| 此网络下的模式由你决定 | 场景将模式交给用户。 |
| 你手动选择了模式；场景会等待你选择“按场景” | 用户手动覆盖了模式。 |

手动覆盖模式后，会显示**将模式交还给场景**一行。点按后场景会重新决定模式。场景有问题时不显示实时状态行。

## 授权

如果场景或配置需要访问网站，页面顶部会显示**需要授权**卡片。参见[groups.md#consent](groups.md#授权)。

## 运行中的场景

下面的区域用于编辑当前运行的场景。

### 路由

**路由**区域中每条路由的副标题显示该路由的流量现在去向：

- 路由问题（如有）；
- 直连路由显示**直连**；固定路由显示目标；
- 其他路由显示当前服务器、所在国家（名称中无旗帜时）、延迟和步骤。

页脚提示：“流量从上到下采用第一个匹配的路由”。

| 操作 | 功能 |
| --- | --- |
| 点按路由 | 组路由打开[组面板](groups.md)；直连路由和固定路由打开[路由编辑器](routes.md#路由编辑器)。 |
| 长按（桌面端右键） | 菜单包含**编辑**和**删除**。 |
| **添加路由**行 | 开始[添加路由流程](routes.md#为单个服务添加路由)。 |
| 标题栏排序按钮（至少两条路由时显示） | 进入排序模式；拖动行后退出。 |

顺序很重要：流量匹配两条路由时，靠上的路由优先。当前不是 rule 模式时，页脚会警告：“路由仅在 rule 模式下生效；当前连接使用 {mode} 模式。”

**其余流量**行匹配任何未被路由接管的流量，显示主组名称以及“组自身配置”或你设置的服务器顺序摘要。点按可为主组设置独立行为和服务器顺序。“我的分流”示例中可在此设置“主流量走挪威”。

### 更多

| 项目 | 含义 |
| --- | --- |
| **连接模式** | 场景是否更改模式：保持不变、rule、global 或 direct。 |
| **场景中的分组** | 可以为指定组和**所有组**（`*` 规则）设置规则。使用**添加组**菜单添加；长按一行可**删除**。编辑方式与路由的服务器顺序相同，但不包含流量条件。 |
| **网络类型** | 网络类型名称（例如“home”）；每项可设置**识别条件**、该网络下的模式及组规则。**添加网络类型**的名称最多 24 个字符，只能使用小写拉丁字母、数字和连字符。 |
| **标签** | 供步骤通过 `tag(name)` 使用的服务器集合名称。最多 24 个字符，可用字母、数字、`-`、`_`。 |
| **高级** | 网络诊断和翻译；此处只读，提示“这些部分通过 YAML 编辑”。 |

文本格式见[scenarios.md](../scenarios.md)。

### 编辑副本

内置场景和服务商场景不可直接修改。首次尝试编辑（例如添加路由）时，ReClash 会询问：

> **编辑副本？** “‘{title}’不是你的场景，无法直接修改。你的编辑会保存到副本，并由副本成为当前运行场景。”

选择**编辑副本**。副本会放入**我的**并立即运行，同时保留来源链接，方便之后[合并原始场景的更改](studio.md#合并原配置的更改)。

### 自动保存与版本

自己的场景在内容有效后会立即保存。应用会为每个场景保留最近 10 个版本，但只有配置工作台支持恢复版本（参见[studio.md#history-and-restore](studio.md#历史记录和恢复)）。路由编辑后，稍等片刻会重新应用一次配置。

## 分组

**分组**区域列出自动路由控制的智能组，副标题格式与路由相同；点按可打开[组面板](groups.md)。执行过检查后，页脚显示 **今日检测：{requests} · 已用 {used}／{cap}**；否则显示“自动路由尚未控制任何组”。能耗行显示今日探测请求数和每日上限。

## 库

最后一行**库**（“场景、行为和导入”）打开库页面。页面顶部是**新建场景**、**新建配置**和**导入**，下方的**场景** | **组配置**切换器用于筛选卡片。

| 筛选项 | 提示 |
| --- | --- |
| 场景 | “场景控制整个连接。点按自己的场景进行编辑；点按其他场景可编辑副本。” |
| 组配置 | “配置决定智能组如何选择服务器。点按自己的配置进行编辑；点按其他配置可编辑副本。” |

### 卡片

卡片显示标题、说明（文件损坏时显示错误）和标签：

| 标签 | 显示位置 |
| --- | --- |
| **内置**、**来自服务商**、**我的** | 所有卡片，表示来源。 |
| **简单**、**高级** | 组配置，表示配置的复杂度。 |
| **需要授权** | 需要访问尚未授权网站的项目。 |

正在运行的场景带有勾选标记。

### 点按和上下文菜单

点按自己的卡片可直接编辑。点按其他卡片会打开副本，保存时才会创建。

长按（桌面端右键）打开菜单：

| 菜单项 | 适用范围 | 功能 |
| --- | --- | --- |
| **编辑** | 我的 | 打开编辑器。 |
| **编辑副本** | 全部 | 创建自己的副本并打开。 |
| **导出** | 全部 | 打开[导出](../sharing.md#导出)。 |
| **删除** | 我的 | 确认“删除‘{profile}’？”后移除。 |

### 新建场景、配置和导入

**新建场景**打开空白场景编辑器；**新建配置**打开[工作台](studio.md)；**导入**打开[导入页面](../sharing.md#导入与解包)。

## 场景编辑器

从库打开场景时，页面包含与运行中场景相同的**路由**和**更多**区域，顶部另有：

- 标题输入框（提示“新建场景”）；
- 说明输入框（提示“此场景的作用”）。

下方显示**警告**和**将访问的网站**。顶部有保存勾选按钮（存在错误或未更改时禁用）和包含**YAML**（文本编辑）、**导出**以及已保存场景的**删除**菜单。

## 关闭自动路由

### 对整个订阅关闭

1. 打开**工具** → **自动路由**。
2. 关闭**自动路由**。

当前场景会被清除。组恢复为普通 select 组，当前服务器保持不变。场景仍保留在库中。

### 对单个组关闭

1. 打开“代理”并点按组，再打开其自动路由面板。
2. 滚动到底部并点按**关闭自动路由**。

这会移除组自身的绑定。只有由你配置为智能组的条目显示此选项；由场景控制的组不显示。参见[groups.md#turn-auto-routing-off-for-one-group](groups.md#关闭单个组的自动路由)。

### 删除单条路由

1. 在**路由**区域长按路由并选择**删除**。

路由及其组会消失；对应流量会匹配下一条路由或进入**其余流量**。

## 操作示例：从空白状态创建“我的分流”

目标设置：

- 主流量走挪威；
- YouTube 使用 ⚡ RU 服务器，否则任意可用服务器；
- Claude 走瑞典；
- Gemini 使用名称中带 `*` 的任意服务器；
- Local 将 `category-ru` 和 `yandex` 网站类别直连。

1. 打开**工具** → **自动路由**。没有运行场景时，页面只显示开关、**分组**和**库**行。
2. 在**库**中点按**新建场景**，保存后在库中点按该场景运行它。（最后再将场景命名为“我的分流”。）
3. 回到自动路由页面，点按**添加路由**。
4. 选择 **YouTube** 服务标签并点按**下一步**。名称会预填“YouTube”和 emoji；保留该名称，**流量通过**保持为 **Auto**。
5. 在**服务器顺序**中点按**添加步骤**。在**此步骤中的服务器**下点按**名称包含**并输入 `⚡ RU`，然后确认。页脚会显示匹配的服务器数量。
6. 再次添加步骤，所有字段留空；步骤显示为**任意可用服务器**。保存路由。
7. 添加 **Gemini** 路由，重命名为“✨ Gemini”。新增一步，设置**名称包含**为 `*`；此处星号是普通字符，不是通配符。
8. 添加路由，不选服务标签，改为点按**添加条目** → **网站类别**，输入 `category-ru`。再添加**域及其子域**条目，输入 `yandex.ru`。点按**下一步**，命名为“🏠 Local”，将**流量通过**设为**直连**。
9. 添加 Claude 路由：选择 **Claude** 服务标签（改名为“🤖 Claude”），新增一步并将**国家**设为瑞典。
10. 使用排序操作调整顺序。具体的路由应排在范围更广的路由之前。
11. 打开**其余流量**并添加一步，将**国家**设为挪威。
12. 在场景编辑器中输入标题 `我的分流` 和说明并保存。
13. 检查自动路由页面，确认路由显示了当前服务器。

相同设置的文本格式见[scenarios.md#routes](../scenarios.md#路由)。
