# 站点锁定

站点锁定会把选定的站点固定到你指定的出口服务器：无论模式、规则或所选代理如何，这些站点的流量只会从其中一台服务器离开，否则就不走网络。其余流量仍按原有路由处理。

## 锁定的工作方式

核心会在应用模式和规则之前，先用已启用的锁定检查每个新连接。匹配某个锁定的连接会被送到出口服务器中最近一次延迟检测通过的第一台；如果全部未通过检测，则送到第一台。当正在运行的配置文件中没有该锁定的任何服务器时，连接会被拒绝。被锁定的站点永远不会走 DIRECT，即使在直连模式下也一样。

出口服务器以其完整定义（名称除外）来记忆，因此重命名服务器不会影响锁定，而地址相同但凭据不同的服务器会被视为不同的服务器。订阅刷新导致定义变化时，锁定会改按名称查找服务器，但仅限地址和端口相同的情况，所以沿用旧名称但已迁移的服务器不算出口，锁定会拒绝连接，直到你重新选择服务器。代理组以及内置的 DIRECT 和 REJECT 永远不算出口。

## 创建锁定

打开 **工具 → 高级配置 → 站点锁定**，点按 **+**。

- **名称** 可选；留空时列表会显示第一个站点。
- **站点** 每行填写一项。
- **例外** 填写即使匹配 **站点** 也不纳入锁定的条目。
- **出口服务器** 显示已选的服务器；**选择服务器** 会打开正在运行的配置文件中的服务器，并可按国家或名称搜索。名称不同但完全相同的服务器合并为一行。该列表仅在核心运行时加载；已保存的服务器无论如何都会保留在锁定中，长按或右键可移除。

| 你输入的内容 | 保存为 |
| --- | --- |
| `chatgpt.com`、`*.chatgpt.com` 或 `.chatgpt.com` | `DOMAIN-SUFFIX,chatgpt.com` |
| 粘贴的地址，例如 `https://chatgpt.com/c/1` | `DOMAIN-SUFFIX,chatgpt.com` |
| `geosite:openai` | `GEOSITE,openai` |
| `1.2.3.4` | `IP-CIDR,1.2.3.4/32,no-resolve` |
| `2001:db8::/32` | `IP-CIDR6,2001:db8::/32,no-resolve` |
| 不带目标的 mihomo 规则，例如 `DOMAIN,api.openai.com` 或 `DOMAIN-KEYWORD,openai` | 原样保存 |

使用各国文字的域名（如 `пример.рф`）也会匹配其 punycode 形式。未带 `no-resolve` 的 `IP-CIDR` 条目会让核心为每个新连接解析域名以比较其地址，这会拖慢与该锁定无关的连接；除非锁定必须捕获解析到该范围内的域名，否则请保留 `no-resolve`。

一个锁定最多包含 128 个条目和 16 台出口服务器，最多可保留 32 个锁定。核心运行时，保存锁定时会检查整份列表：如果核心拒绝某个条目，编辑器会保持打开并显示该条目及原因，之前的锁定仍然有效。核心停止时保存的锁定会在核心启动时检查；届时被拒绝的锁定会连同原因一起显示，并且不会生效。

## 预设

页面标题栏有 **从预设添加**，包含 Claude、ChatGPT、Gemini、Grok、Perplexity、DeepSeek 和 Cursor。选择其一会创建一个跟随该预设的锁定，并打开编辑器供你选择出口服务器。编辑器会在 **站点** 上方显示该预设：其 geosite 列表、域名后缀和地址范围会随 ReClash 更新，你在 **站点** 中添加的条目则叠加其上。长按或右键点击该预设可解除关联，并把它的条目复制到 **站点** 中供你编辑；此后该锁定不再接收更新。这些服务会标记 IP 地址发生变化的账号；锁定可让它们保持在你选择的服务器上。

## 状态

| 状态 | 含义 |
| --- | --- |
| 经由 *服务器* | 被锁定的连接从该服务器离开。 |
| 所有出口均不可用 | 每个出口的最近一次延迟检测都失败了；连接仍会尝试第一个。 |
| 配置文件中没有出口服务器 | 正在运行的配置文件中没有该锁定的任何服务器，因此被锁定的连接会被拒绝。 |
| 已关闭 | 该锁定已禁用。 |
| 等待核心 | 核心尚未报告此锁定。 |

## Linux 上的隧道外防护

在 Linux 上启用 TUN 并安装 Helper 后，Helper 还会在系统防火墙中保持该锁定。它需要 `nft` 命令（`nftables` 软件包）；缺少时页面会提示该软件包未安装。ufw、firewalld 和 iptables 仍可并行工作：ReClash 添加自己的表 `inet reclash_sitelock_<uid>`，不会修改它们的配置。被锁定的地址会在除 ReClash TUN 之外的所有接口上被拒绝，包括其他 VPN 的接口。fake-ip 范围仅在物理接口（如以太网和 Wi-Fi）上被拒绝，不包括其他隧道接口（tun、WireGuard），因此使用相同 fake-ip 范围的另一个 VPN（例如其他基于 mihomo 的客户端使用 `198.18.0.0/16`）可以并行运行。在 ReClash TUN 之外对被锁定名称发起的 DNS 查询仍会进入 TUN 或被丢弃，所以并行的 VPN 无法打开被锁定的站点。对被锁定名称的 DNS 查询不会被丢弃：Helper 会把它送入隧道，核心返回一个 fake 地址，名称因此得以解析，连接从被锁定的出口离开。其他所有 DNS 查询原样通过，因此只有家用路由器或另一个 VPN 才知道的名称仍可正常解析。核心停止或崩溃期间不存在隧道，所以对被锁定名称的查询会被丢弃，封锁依然生效；Helper 还会在开机时、ReClash 启动之前恢复该封锁。按名称设置的例外在此同样适用；按地址设置的例外则不适用，因此这样的地址在隧道外仍被封锁。如果有东西清空了防火墙，例如防火墙服务重启，Helper 会在约 10 秒内恢复锁定。若要直接访问被锁定的站点，请关闭其锁定。如果关闭最后一个锁定时 Helper 没有运行，防火墙会一直封锁，直到 Helper 恢复；页面会提示这一点，而 ReClash 会在 Helper 响应后立即解除封锁。

> [!IMPORTANT]
> 锁定启用期间，隧道外的每个 DNS 查询都会经过 Helper。如果 Helper 停止，这些查询也会随之中断，而不是发生泄漏。

若要自行检查规则，请运行 `sudo nft list table inet reclash_sitelock_<uid>`，其中 `<uid>` 是 `id -u` 的输出。

只有经 IPv4 和 UDP 发出的、针对被锁定名称的查询会进入隧道。Helper 无法解析的查询（例如分片的查询），以及经 IPv6 或 TCP 发出的、针对被锁定名称的查询，会被直接丢弃而不予应答，因此应用程序会等到自己的超时。

## Windows 上的隧道外防护

在 Windows 上启用 TUN 并安装 Helper 后，Helper 会在 Windows 筛选平台（Windows Filtering Platform）以及 DNS 客户端的名称解析策略中保持该锁定。在 TUN 接口之外，Windows 会在除 TUN 之外的所有接口上拒绝到被锁定地址以及隧道 DNS 地址的连接。fake-ip 范围仅在以太网、Wi-Fi 和 PPP 接口上被封锁，因此并行的 VPN 与在 Linux 上一样可以工作。被锁定的名称（完整名称和后缀）只由隧道的 DNS 解析，所以核心返回 fake 地址，连接从被锁定的出口离开；其他所有名称的解析方式不变。核心停止或崩溃期间不存在隧道，因此被锁定的名称无法解析，封锁依然生效。这些筛选器和规则在没有 Helper 的情况下也会在重启后保留。如果有东西移除了它们，Helper 会在约 10 秒内恢复，卸载 Helper 则会解除它们。如果 Helper 已损坏，或在未卸载的情况下被删除，请在管理员终端中从 ReClash 文件夹运行 `ReClashService.exe lift-site-lock`：它会停止 Helper 并移除这些筛选器和规则，同时也会解除[断网保护](kill-switch.md)。关闭最后一个锁定的行为与 Linux 相同。

Windows 与 Linux 有三点不同：

- **关键字和正则表达式**：名称解析策略只匹配完整名称和后缀，因此 `DOMAIN-KEYWORD`、`DOMAIN-REGEX` 和 `DOMAIN-WILDCARD` 条目，以及 geosite 列表中的关键字和表达式，仅由核心处理。
- **例外**：无论按名称还是按地址设置的例外，在隧道外都不适用，因此在核心停止期间，被锁定后缀下的例外名称无法解析。
- **共享连接**：Windows 为其他设备转发的流量（例如移动热点）不会被过滤。

在名称解析策略来自域组策略的计算机上，Helper 会把自己的规则添加到该策略中，而策略刷新可能会将其移除，直到 Helper 将其恢复。

## 页面上的系统防火墙

在 Linux 和 Windows 上，锁定页面会显示 **系统防火墙** 分组，包含 **机制**（nftables 或 Windows 筛选平台）、**状态**（正常或存在的问题）、**已拦截的地址**、**由 DNS 过滤的名称** 以及 **不允许进入物理网络的 fake-ip 范围**。**显示规则** 会打开实时规则；在 Linux 上它还会显示用于检查规则的 `nft` 命令。

## 移除 ReClash

> [!IMPORTANT]
> 在 Linux 和 Windows 上，系统防火墙通过 Helper 强制执行锁定。ReClash 关闭或崩溃时它仍然有效，并且从开机起就生效，只有关闭所有锁定才会解除。DEB 和 RPM 软件包以及 Windows 卸载程序会移除 Helper 及其规则。对于 Linux 上的 AppImage 或手动安装，请先使用 **工具 → 核心 → 移除 Helper**，或在删除应用之前关闭这些锁定。

## 在 Android 上

Android 没有可用于锁定的防火墙层，但锁定开启期间，ReClash 会堵上其自身 VPN 会留下的缺口：

- **禁止绕过**：无论 **工具 → 网络 → 允许应用绕过 VPN** 如何设置，应用都无法绕过 VPN。该设置保留其值，并在所有锁定关闭后重新生效。
- **路由**：被锁定的地址和配置文件的 fake-ip 范围始终进入隧道，即使 **路由地址** 只列出部分网络或绕过了私有网络。使用默认路由列表时，所有流量本来就会进入隧道。
- **被排除的应用**：被 **访问控制** 排除在 VPN 之外的应用，或在“仅所选应用”模式下列表之外的所有应用，会在没有锁定的情况下访问被锁定的站点。页面会对它们发出警告。
- **断网保护**：仅限 Android。页面会显示 ReClash 是否已开启 Android 的 **始终开启的 VPN** 与 **屏蔽没有 VPN 的连接**，并可打开系统 VPN 设置。开启后，Android 会在 VPN 关闭期间阻止流量，因此 ReClash 停止时被锁定的站点保持不可访问，但其他所有流量同样如此，并且被排除在 VPN 之外的应用可能会失去网络访问。

这些选项在 VPN 启动时生效。VPN 运行期间开启或关闭锁定，或更改其地址，会像其他 VPN 设置一样提示重启 VPN。

## 限制

- **macOS** 只有核心层：核心停止后，没有任何东西封锁被锁定的站点，也没有断网保护。
- **Linux 和 Windows**：桌面[断网保护](kill-switch.md)会封锁 TUN 之外的所有流量，而不仅是被锁定的站点。
- **Android** 只增加上述 VPN 措施：核心停止后，只有系统断网保护会封锁被锁定的站点。
- **关闭 TUN**：锁定只覆盖经过核心的流量，系统防火墙不会封锁任何内容。
- **嗅探**：域名条目按连接的名称匹配，而核心自己没有解析过名称的连接（例如使用自带 DNS 的浏览器）会以裸地址到达。因此，只要有带域名条目的锁定处于开启状态，即使配置文件没有嗅探器，核心也会在常用端口上从 TLS、HTTP 和 QUIC 读取名称；自行设置了嗅探器的配置文件则保留其设置。名称只用来选择规则，连接仍然前往同一个地址，但配置文件中的域名规则现在也可能捕获这类连接。
- **Encrypted Client Hello**：使用 ECH 隐藏站点名称的浏览器（如 Chrome 和 Firefox 对许多 Cloudflare 站点所做的那样）只会暴露提供商的公开名称，因此除非核心自己解析了名称，这样的连接只会匹配地址条目。
- **仅核心条目**：系统防火墙无法镜像的条目，例如取反的 geosite 属性、带有环视的正则表达式、逻辑规则或端口规则，以及 Windows 上的关键字和正则表达式，只在核心运行期间生效。页面会列出包含这些条目的锁定。
- **提供商侧变更**：锁定比较的是配置文件中的服务器定义，而不是流量最终离开时使用的地址。如果提供商在同一台服务器背后更换了出口 IP，或将服务器的域名指向另一台机器，仍然满足该锁定。
- **未列出的域名**：服务中任何条目都未覆盖的域名会遵循配置文件的规则。预设涵盖的是构建时观察到的请求；请检查该服务实际连接了哪些域名，并补充缺失的部分。
- **浏览器中的加密 DNS**：DNS over HTTPS 和 DNS over TLS 会绕过 Helper 的 DNS 过滤器。核心运行时这没有影响，但崩溃之后，这样的浏览器可以解析并访问被锁定的站点。请在浏览器中关闭安全 DNS：Chrome 位于 **设置 → 隐私和安全 → 安全 → 使用安全 DNS**，Firefox 位于 **设置 → 隐私与安全 → DNS over HTTPS**。
- **硬编码地址**：通过已知地址直接连接的应用程序只会被地址条目捕获。对于这样做的服务，请添加 `IP-CIDR` 条目。
